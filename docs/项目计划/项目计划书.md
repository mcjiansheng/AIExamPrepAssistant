# AI 备考助手项目方案

状态：讨论稿，更新于 2026-11-06。数据结构版本 v0.2。

项目背景：大学生鸿蒙开发项目，团队约 3 人，计划使用 vibe coding，目前没有上线计划。报告目标是 2026-11-13 前完成。开发时长为 1 到 2 个月，本方案按最长 8 周排期，第 4 周完成 P0。

## 1. 问题与定位

大学生在期中、期末要在有限时间内复习并通过考试。本项目用已有课件和最后一节课的重点，生成备考计划，进一步生成模拟试卷。

“课件生成题目”已有不少同类产品（如 StudyPolar、UExam、Studocu AI）。建议的差异化方向：

- **利用划重点信息：** 把老师的口头重点、板书照片或录音转成知识点权重。
- **按剩余时间取舍：** 明确哪些必学、哪些可以放弃。
- **三级知识：** 用校内和跨校知识补足单人资料，用个人知识网络打通多门课。
- **适配国内场景：** 重点支持中文课件、国内课程题型和鸿蒙设备。

## 3. 三级知识模型

| 层级 | 范围 | 内容 | 主要用途 |
|---|---|---|---|
| 个人知识 | 用户本人，可跨课程 | 自己的资料、错题、掌握度、跨课程知识网络 | 决定复习重点和个性化解析 |
| 校内知识 | 同课程、同教师、同专业或同一次开设 | 统计信号；权利方允许时可含文本 | 贴近本校本课的考点和风格 |
| 共享知识 | 跨学校 | 标准知识点、统计信号、开放许可资料 | 新课程冷启动和通用知识结构 |

### 核心原则

**进入模型上下文的内容，必须是当前用户本来就有权直接看到的内容。**

提示词中的“不要输出原文”不能算隔离手段。研究显示，RAG 知识库内容可能被诱导提取，所以权限必须在检索模型上下文之前判定。

### 使用时的优先级

个人知识和老师重点决定主要权重，校内信号最多调整 0.2，共享信号最多调整 0.1。这些上限是暂定值，要按实测调整。

### 资料如何向上流动

| 资料形态 | 进入校内 | 进入共享 |
|---|---|---|
| 统计信号 | 权利依据明确、用户确认、审核通过、未被拒绝 | 条件相同 |
| 文本内容 | 本人创作且审核通过，或权利方明确允许 | 开放许可，或权利方明确允许 |

- **信号门槛：** 校内和共享信号都至少需要 3 位贡献者。
- **往年卷：** 进入校内或共享层，都需要已验证的明确授权。
- **默认不外传：** 没有明确依据的资料留在个人层。
- **本学期试卷：** 不进入共享流程，状态不明的试卷按同样规则处理。
- **用户确认：** 只是必要条件，不能单独放行教师或学校的资料。

### 学校、专业、教授策略

- **命中范围：** 策略可以设在学校、院系、专业、课程、教师或单次开设上。
- **多条命中：** 取最严的结果。
- **放行与收紧不对称：** 只有已验证的策略能放行；待审核的策略只能收紧。这样拒绝可以先生效，冒充的授权不会生效。
- **撤回：** 信号在服务端记录来源资料 ID，策略变化后可以定位、撤回并重算。这些 ID 不返回给客户端。
- **教师未回应时：** 不阻塞产品，统一走默认规则，只流通符合条件的统计信号。

### 个人跨课程知识网络

以同时学习 Java 和 C++ 为例：

| 关系 | 示例 | 用途 |
|---|---|---|
| 类比 | Java 接口 ↔ C++ 抽象类 | 用熟悉的概念解释新概念 |
| 对比 | Java 引用 ↔ C++ 引用 | 提醒容易混淆的差异 |
| 同一概念 | 两门课中的封装 | 合并复习，减少重复 |
| 前置知识 | 指针 → 动态内存管理 | 排定复习顺序 |

规则：

- 链接只连接本人知识点，不参与共享。
- AI 建议的链接由用户确认后才能用于解析。
- **跨课程内容不能扩大考试范围**：试题考点必须属于当前课程，另一门课只能出现在解析里。

## 4. 核心流程

1. **解析资料：** 把 PPT、PDF、照片和录音转成结构化文本，并保留页码。
2. **构建知识点：** 按章节整理，并映射到标准知识点，作为三级知识的连接点。
3. **计算权重：** 以老师重点和本人资料为主，再用校内、共享和联网信号微调。
4. **生成计划：** 根据考试日期、可用时间和掌握度排期，并明确可放弃的内容。
5. **生成试卷：** 先定题型、分值和知识点分布，再逐题生成，标注出处并独立校验答案。
6. **批改并调整：** 根据错题定位薄弱点，更新后续计划和个人知识网络。

## 5. 技术方案

### 客户端

本期建议鸿蒙原生为主：

- **ArkTS/ArkUI：** 负责页面框架、课程管理、文件选择、录音、复习计划和本地通知等主要体验。
- **ArkWeb：** 只负责试卷和公式渲染，复用 KaTeX 这类成熟 Web 库。
- **后端：** 文档解析和模型调用放在一个小型 API 服务中，模型密钥只留在服务端，不打包进应用。
- **其他平台：** 本期不交付。试卷渲染页和后端 API 可以复用，以后再补 Web 或 Electron 客户端。

调整原因：这是鸿蒙开发项目，原生能力更能体现项目重点。如果项目规则不要求原生，也可以退回 Web 核心方案。

文件上传已有官方路径：可以用 `DocumentViewPicker` 选择文件；若使用 ArkWeb 上传，可通过 `onShowFileSelector` 接管选择器。**开发第一周仍要用真机验证文件上传、录音和公式渲染。**

### Vibe coding 规则

通用 AI 工具写 ArkTS 的效果未必理想，公开训练数据也相对有限。可以优先试用华为的 DevEco Code 或 DevEco CLI，它们集成了 DevEco 工具链、鸿蒙知识库和官方 Skills。这部分基于公开介绍，尚未实测。

- **先定接口：** 先固定 JSON Schema 和 API，鸿蒙端和后端再分别生成代码。
- **小步提交：** 每个提示词写清目标、可改文件、不能破坏的行为和验收标准。
- **互相审查：** AI 生成的代码合入前，由另一位成员看差异。
- **自动检查：** 每次提交运行构建和 `validate_exam_prep.py`。
- **核对陌生 API：** 用 DevEco Studio 的类型提示和官方文档确认，AI 的 UI 验证结果也要回到真机检查。
- **保护密钥：** 签名私钥和 API 密钥不进入对话或仓库。

### Agent 工具

| 工具 | 适合用途 | 风险 |
|---|---|---|
| DeepSeek Harness | 内部验证流程和提示词，可用 Trajectory 视图调试 | 仍是开发者预览版，会有破坏兼容性的改动 |
| Pi | 产品阶段按需接入统一 LLM API 和 agent 运行时 | 没有内置权限系统，需要自行隔离 |

这两项判断基于文档和报道，尚未实际运行验证。

- **完整设计：** 单一模型的 agent 工作流见 `docs/设计/单一模型Agent工作流设计.md`。
- **本期做法：** 用 DeepSeek Harness 和原型工作流作对比，看固定流程与 Agent 自主检索哪种更好；Pi 本期不接入。
- **不直接暴露给用户：** 产品主流程写成自己的后端服务，每个 agent 任务都放进隔离环境，不开放 shell 权限。
- **少用自主 agent：** 解析、权重和排期用普通代码；知识点提取和出题用固定步骤的模型调用；只有资料搜索和答案复核适合 agent。
- **避免绑定框架：** 数据结构放在自己的模块里。

### 联网查找往年资料

| 等级 | 来源 | 用途 |
|---|---|---|
| A | 用户上传的课件、老师重点 | 决定范围和主要权重 |
| B | 用户确认的本校本课程往年卷 | 参考题型、分值和考点频率 |
| C | 网上找到、能对应同校同课程的试卷 | 仅微调权重，并标注“未验证” |
| D | 通用题库、论坛 | 仅作练习素材或风格参考，不影响权重 |

- 超出课件和老师重点的内容，最多标为“可能超纲”。
- 只保存链接和统计结果，不转存或公开原卷，不绕过登录、付费墙或网站限制。
- 网上答案要依据课件重新校验，来源不明的题不能标成“真题”。
- 搜索 agent 只能联网读取并输出结构化结果，不能有 shell 或文件权限。

## 7. 原型进度

原型代码在成员本机的 `exam-prep-prototype` 文件夹，说明见`docs/原型/原型说明.md`。课件文本库不放入项目。

已完成（2026-11-06）：

- **知识库：** 操作系统、商务智能、高级算法的全部课件和作业，共 42 份，按页保留出处，作业中的姓名学号已遮蔽。
- **版本判定：** 按内容分组，按内嵌日期、内容包含和文件名日期判定最终版，证据不足时请用户确认。模型不参与判定。实测从证据判出第三章的最终版是 20260420，与成员确认一致。
- **错放资料：** 高级算法文件夹中的作业实为操作系统作业的空白模板，已按内容归类，并被已填写版本取代。
- **图示：** 约 1900 页已渲染，等待视觉模型转写，结果标注来源。
- **三级权限：** 所有文本读取都先判定权限，已覆盖撤销授权、待审核授权、待审核拒绝、未验证用户和外校用户等场景。
- **工作流：** 全量建库、知识点去重、盲答复核、断点续跑已实现。原型阶段不限制输出、调用次数和上下文。
- **真实运行：** LongCat 连接和知识点抽取已跑通；首次运行因给复核设置 2000 token 上限，被思考过程用完而失败，已取消上限。

真实运行结果（2026-11-06）：

- **建库：** 35 份最终版，1138 个知识点，1904 页图示识别完成。这次运行用量约 237 万输入和 146 万输出 token。
- **检索：** 28 条查询 Top1 从 15 条升到 23 条，Top5 从 18 条升到 27 条。
- **题目：** 人工核对 29 道题，结论都正确，5 道存在推理、解析或选项问题；第一版复核全部放行，说明不能只看通过率。已加强出题和复核提示词，待重跑验证。
- **跨课程链接：** 8 条候选中约 4 条有学习价值，其余依据人名或类比牵强，已收紧规则。
- **第二轮（加强出题和复核提示词后）：** 29 道题结论都正确，计算和应用题明显增多，如磁盘调度总移动量、银行家算法请求、开地址哈希、递归树求解。仍有 4 道小问题（动态规划表格一格算错、平均值与单次结果混比、B(T) 定义与课件不一致、选项存在歧义），复核全部一次放行。跨课程链接 5 条，不再依据人名，约 3 条有用。
- **结论：** 出题质量已接近可用，瓶颈在同一模型复核。计算题适合改为程序验证，其余题需要另一个模型或人工抽查。
- **单一模型验证组（2026-11-07，已实现，待真实评测）：** 按 `docs/设计/单一模型Agent工作流设计.md` 完成第 1 到 5 步：结构化题目、沙箱程序验算、盲解代码、独立作答、逐步核对、推导连贯、选项反驳和引用核对，由代码裁决、修订和替换知识点。用两轮人工核对的 34 道题（9 道有问题）做回归集，目标拦下至少 7 道、误报不超过 3 道。离线测试 80 项通过。

未验证或未实现：

- 用真实期末卷验证知识点覆盖率和超纲率。
- DSH 固定工作流和 Agent 自主检索的对比。
- 向量语义检索、共享层真实统计信号。

## 8. 风险

### 合规

这里只是初步梳理，不是法律意见，部分依据来自二手资料。面向公众上线前应请律师确认。

本期不上线，所以备案和公开服务相关事项可以后置。但版权和隐私仍要注意：测试只用本人笔记、获得许可的资料或自制样例，共享层使用模拟数据，也不公开他人的课件和试卷。

- **用户确认不等于授权：** 课件权利通常属于教师或学校，确认记录只能证明用户作过声明。
- **存储平台责任：** 免责条件包括不知道也不应知道侵权，以及收到通知后及时删除。收到合格通知后不处理，可能被认定为“明知”。
- **生成内容责任：** 提供者承担内容生产者责任，生成内容未必能套用“用户上传”的免责思路（此点为推断）。
- **备案：** 向境内公众提供生成式 AI 服务需要确认备案和登记要求。
- **生成内容标识：** 需要落实 AI 生成内容标识要求。

### 产品与安全

- **题目错误：** 错误答案会直接误导复习，需要出处追溯、独立校验和一键报错。
- **宣传口径：** 不承诺“押题”，只说明知识点覆盖情况。
- **教师确认的规模：** 逐位联系成本高，建议先在少数课程试点。
- **策略冒充：** 教师身份需要可靠验证，还要防止恶意提交拒绝策略。
- **小班课程：** 不足 3 位贡献者时不生成信号，这类课程主要依靠个人知识。
- **信号污染：** 需要防范虚假上传和批量注册。
- **个人数据：** 个人知识网络和错题属于用户数据，需要支持导出和删除。

### 3 人分工

- **鸿蒙端：** ArkUI 页面、文件和权限、ArkWeb 试卷渲染、真机测试。
- **后端与 AI：** API、文档解析、提示词、出题和答案校验。
- **产品与评测：** 收集样例、评测题目质量、编写报告，同时负责审查合入。

### 时间风险

开发期不一定遇上考试，如果跨越寒假，学生更没有真实备考需求，用户测试不容易开展。所以要**趁本学期期末前收集样例**：记录最后一节课的重点，取得所需许可。开发期以离线评测为主，真实使用留到下学期期中。

### 效果指标

找几门有真实期末卷的课程，把真题藏起来再生成模拟卷：

- 模拟卷对真题知识点的覆盖率
- 超纲率
- 助教或学长判定的题目正确率
- 学生是否真的按计划复习
- 加入校内、共享或联网信号后，覆盖率提升多少、超纲率是否上升

某一层没有明显提升，就不必急着上线。
