# 后端 API v0

2026-11-24，后端与 AI，`backend/api-v0`。

## 修改

- `server/app.py` 在本机提供 WebUI 和 API。课程、资料、知识点、计划、试卷、作答事件和对话写入 SQLite。解析、分析重点和出题按阶段保留已完成的产物。
- 资料上传支持批量处理，版本和资料角色的建议按默认选项先行生效。新版沿用文字层未变的页与知识点，旧题引用失效时标记待复查，保留原作答。
- 重点按片段分析。第一步召回主题，第二步三次独立选择知识点。口头重点、复习讲义和笔记共同提供计划依据。
- 计划按学习时长和重点取舍，预留约 20% 给模拟题与错题，重排保留用户固定项。出题先写入可查询的试卷，题目验证完成后逐道可答。计算题求解反复失败时改出简答题。
- 助手使用现有操作完成重排、固定、记录重点、勾选与出题。计划等改动可撤销。考试形式和资料删除走提议确认。作答前答案留在后端，用户明确要求后才返回，并记录看过答案。
- 练习页读取出题 Job 的失败状态，显示原因和可用的操作。题目报错只记录并隐藏题目。前端设计方的三次提交分别为 `50c6d2f`、`ea43760` 和 `5d0d488`。

## 验证

- `python3 -m unittest discover -s server/tests` 15 项通过。离线测试覆盖真实 HTTP、合同字段和主要状态，含混合上传、重试、资料版本切换、解析期间删除、计划固定、判分、报错、撤销和答案保护。
- `python3 server/app.py --mock-model` 启动后，用本机 Chrome 走查了课程增删改、上传两份资料、分析重点、生成和固定计划、完成五题并报错、查看结果、重排、助手讲解、撤销、考试形式确认和做题提示与公布答案。浏览器另外验证了出题失败原因和停止轮询。模拟和真实结果的截图都在 `local/证据/`。
- 真实 LongCat 冒烟一次。导入 30 页课件，得到 38 个知识点与 30 张页图。两句重点均找到内容，生成五道通过检查的题。助手五轮均结束，两轮讲解各返回五条出处，重排与出题各执行一次，提示轮给出一条出处。
- 真实调用 127 次，其中 126 次成功。服务返回的用量为 115,466 输入和 35,620 输出 token，合计 151,086。一次失败请求没有用量回包，按上界计入后为 166,752 token，低于 600,000 上限。只统计数字的本地记录为 `local/证据/后端-v0-真实冒烟.json`。
- `python3 schema/validate_exam_prep.py` 在现有环境缺少 `jsonschema`，未能执行校验。项目未增加依赖，`schema/` 和 API 合同未修改。

## 实现说明

- 原生 `tools` 的三次实测均未返回可执行调用，该次冒烟使用 JSON 意图。探测复用了要求输出 JSON 的指令，结果只说明那三次请求未走原生工具，不能单独判定 LongCat 的原生工具稳定性。产品默认采用已跑通的 JSON 意图。原生指令已单独拆出，改动后的原生探测未再次调用真实模型。[LongCat Responses API 文档](https://longcat.chat/platform/docs/api/responses)
- 真实冒烟后补了版本与中断处理、聊天记录和作答响应的回归修复。对应修改用离线 HTTP 测试和模拟浏览器流程复验。
- 同一浏览器标签页用上传回包保存资料与 Job 的关联，可重试该任务。没有这份关联的客户端可重新上传。跨客户端查询这份关联需要双方确认接口调整。
- 本次没有创建或验证鸿蒙工程。题目报错后的自动复查留在后续工作。
