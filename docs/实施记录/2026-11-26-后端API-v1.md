# 满格服务端 API v1

日期：2026-11-26（PST）。工作线：后端与 AI。分支：`backend/api-v1`。接口依据：合同 v1.1、核心流程细节 09 和后端交接。

## 第 1 段：骨架与账号

- `server/v1/` 提供 FastAPI 入口、编号 SQLite 迁移、请求 ID、JSON 请求日志和合同错误响应。使用 WAL、外键和写事务。运行入口为 `python3 -m server.v1 --mock-model`。
- 实现短信验证码与限流、访客、扫码登录 API、华为假登录、设备退出、访问令牌和轮换刷新。数据库只保存令牌哈希，重放已换过的刷新令牌会吊销所在设备。
- 实现账号资料、设置、提醒、记忆、设备、反馈、学习位置及通知的接口。设置支持撤销，同一行被后续写入后原撤销失效。反馈的幂等记录和写入共用一个事务。
- 任务状态与暂停、继续、重试接口落库。写入提交后，事件流按用户推送变化。已连接的事件流按设备会话持续，重新连接要带有效访问令牌。
- 真实联调测试整轮只发一次演示账号验证码，把会话提供给需要演示账号的用例。新号码注册仍走原来的浏览器短信登录流程。

## 第 1 段验证

- `TZ=America/Los_Angeles server/.venv/bin/python -m unittest discover -s server/tests` 通过 43 项，其中 27 项 v0、16 项 v1。v1 覆盖登录、认证失败、令牌轮换、扫码、归属、账户设置、撤销、幂等和异常日志。
- `server/.venv/bin/python schema/validate_exam_prep.py` 通过，20 个违规用例按预期被拒绝。
- 前端类型检查、8 条单测和演示后端 Playwright 10 项通过（6 条流程、4 种尺寸的 60 张截图）。用新真实联调初始化脚本，在两个独立用例里读到同一演示账号，临时数据库只记录一条演示号码的短信申请。
- 在本机 Chrome 用 `?api=real` 打开两个独立浏览器会话，同一个手机号分别登录。在第二个会话切换深色和浅色，第一个会话两次都自动更新。第二个会话退出时收到 204 并回到欢迎页。
- 真实模型用量 0 token。账号删除、导出及真实模型冒烟按交接留到第 6 段。
