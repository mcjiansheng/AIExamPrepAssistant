日期：2026-11-24。工作线：后端与 AI、鸿蒙端 / 前端（同一人负责合同、后端、前端，用户确认）。分支：`backend/api-v0` 工作区，未提交。

依据：PR #1 项目审查的 1.1（模型失败后永久停用）、1.2（作答页助手所有问题都回固定提示），以及用户确认新增的“出题失败”状态。

## 修改

**接口合同 v0.1**（`docs/接口合同/api-v0.md`）

- `Exam.status` 新增 `failed`：出题任务结束时一道可作答的题都没有。部分没出成仍是 `ready`，任务记为失败并可“继续出题”。
- 出题前就能判断的空题：范围内没有可出题的知识点、考试形式题量全为 0、选“错题相关”但没有错题，`POST /courses/{cid}/exams` 直接返回 409 并说明原因，不建试卷。
- 新增 `DELETE /exams/{eid}`（204）。
- 重试只重做没成功的部分：资料只重跑失败的、出题只重出没出成的题，出好的不动。
- `ready` 试卷完成时，没出成的题删除、不计分；`failed` 试卷不能完成（409）。

**后端**

- `model.py`：去掉“连续失败后整个模型客户端停用”的状态（审查 1.1）。每次调用独立：网络或 5xx 由任务层退避重试，连续 5 次后任务失败、可重试；401/403 直接失败、可重试，提示检查密钥。退避重试的提示改为“……，稍后自动重试”，最终失败改为“……，连续 5 次没有成功”。
- `core.py`：任务结束和重试时调用各模块的钩子；课程“练习”步骤按最新一套题的状态显示，`failed` 显示“需要你看一下”。
- `exams.py`：任务结束定状态（`settle`）；重试时把放弃的题按原规格重新排队（`prepare_retry`）；删除试卷；试卷总分和题数不含没出成的题。
- `chat.py`（审查 1.2）：作答页的问题先走意图识别，问这道题才讲；“这题怎么想”给提示（调模型、看课件原页），“直接告诉我选什么”给答案并记为“看过答案”，其他问题（重排计划、出题）照常执行。模型给的提示如果说出了答案（单选字母、数值答案、主观题大段原文），换成通用提示并记日志。

**前端**

- 练习列表：状态显示“出题中 / 做到 x / y / 得分 / 出题失败”。
- 作答页：部分没出成时顶部提示原因和“继续出题”，没出成的题号点变淡划掉，不计入进度；完成前确认一次。整套没出成时只显示原因、“重试”或“返回练习”、“删除这套”。
- 演示后端：实现上面的状态、409、删除；`?fail=exam`、`?fail=exam-part` 模拟两种失败。演示助手在作答页只在问这道题时才讲题。
- `docs/设计/前端交互设计.md` 4.5、4.6 同步。

## 实现说明

- 为什么部分失败仍是 `ready`：已经出好的题能做，比整套作废有用；没出成的题由用户决定继续出还是放弃。
- 为什么不在出题时“少出几道就算成功”：少了要让用户知道原因，并能补出来；静默少题会让总分和题型分布对不上考试形式。
- 泄露检测是兜底，不是主要手段：出提示的模型本来就拿不到答案，这一层防它自己把题做出来再说出口。
- 合同改动按 AGENTS.md 应单独开只含合同的 PR，提交时由本地 agent 拆分。

## 追加：冒烟反馈的修复（2026-11-25，设计方）

依据真实冒烟报告 `local/交接/真实冒烟报告-v0.1-20261125.md` 的 3.1 第 2 条和 3.2 节。

- **“连续 5 次”按真正的连续计数**：出题时每拿到一个模型结果就清零失败计数；任务失败时从库里读当前计数，不再用领取任务时的旧值（原来即使中间成功过，也会把整道题里零散的失败累加到 5 次）。资料整理判断“第 5 次失败”时同样改为读当前计数。
- **单选选项不再重复字母**：出题提示要求选项只写内容；模型仍给出“A. ”“B、”这类按顺序的前缀时，入库前去掉。
- **作答页提示不能靠排除法给答案**：提示词要求不逐个评价或排除选项；提示里把其余三个选项都点名评过（字母或选项原文）时，按泄露答案处理，换成通用提示。
- **练习列表可以删除任意一套**：每行加“⋯”，打开后“删除这套”，确认后删除。失败页的“删除这套”保留。

验证：

- `cd server && python3 -m unittest discover -s tests`：25 个测试通过（新增 2 个：每步先失败两次再成功的出题任务能完成；带“A. ”前缀的选项入库后去掉前缀。泄露判定加了排除法的正反例）。去掉清零后，新测试会失败。

## 追加：计算题只派给可计算的知识点（2026-11-25，设计方）

处理上一节的遗留优化点。

- **原因**：配题时计算题找“计算与模拟”类知识点，找不到就落到第一个知识点上照样出计算题。这样的题核对必然失败，先换一次知识点再降级为简答题，一道要耗 5–6 万 token。补测里 D、E 每套都有这样一道。
- **修改**（`server/exams.py`）：找不到可计算的知识点时，这一题直接按简答题出，分值不变，题目提示“资料里没有适合出计算题的知识点，这道按简答题出”。有多个计算题名额时，可计算的知识点用完后剩下的同样改简答。与设计修订 v2 考法表里“计算与模拟类出计算题”一致，不改设计结论。
- **测试**：演示模型给含“计算、求解、相加、相乘、乘法”的知识点标上计算考法，用来区分两种知识点。`test_hard_failure_swaps_spare_at_most_once_and_calc_falls_back_to_short` 原本用的是不可计算的知识点，按新规则一开始就会出简答题、测不到降级路径，所以把它的课件内容改成可计算的（“计算甲”等），测的降级行为不变；`test_calc_with_bad_solver_becomes_short` 的课件是“乘法”，本来就算可计算，不用改。新增 1 条：两道计算题、只有一个可计算知识点 → 第一道是计算题且落在该知识点，第二道是简答题并带提示，求解只调用一次。

验证：

- `cd server && python3 -m unittest discover -s tests`：26 个测试通过。去掉改简答的那一行，新测试失败。
- 真实模型核对（同一门课、默认考试形式出 5 道题，范围 `all`）：**仍触发计算题调用，已按交接规则停下汇报**。原因：该课程 21 个知识点中有 4 个在入库抽取时已被模型标上 `compute` 考法，因此第 3 题依然配为 `calc` 且在 `verifying` 阶段反复重试；截止停下时仅前 2 题就绪、第 3 题未完成，已消耗 **38 次调用 / 53,352 token**（其中 `cfexplain` 32,027、`cfproblem` 10,531、`readback` 1,307，其余 `v4/question/v3/v6` 9,487），未出现预期中的“无计算调用且明显低于 74,479”。
