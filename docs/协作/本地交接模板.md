# 本地交接模板

用于把需要真实模型或本机环境的工作交给本地 agent 代跑。由现有原型的 `HANDOFF.md` 提炼而来。

模板本身可以进仓库；**填好的交接文档和代跑报告留在本地**（原型目录或仓库的 `local/`），因为里面可能有课件内容和本机路径。结论由负责人写进 `docs/实施记录/`。

```markdown
# 实验交接文档

写给接手运行实验的 agent。更新于 <日期>（第 <n> 轮）。

## 0. 进度
| 轮次 | 内容 | 状态 |
|---|---|---|
| 第 1 轮 | <实验> | 已完成，报告在 `<路径>` |
| 第 <n> 轮 | 本文第 5 节 | 待运行 |

前几轮的结果不要重跑，也不要覆盖。

## 1. 你要做什么
在这台电脑上，用真实模型运行第 5 节列出的脚本，把结果原样交回。
你的职责是**运行和如实报告**，不是改进设计，也不是让结果变好看。

## 2. 背景（三句话）
<项目是什么；这轮实验要回答什么；想了解更多读哪里>

## 3. 环境
| 项目 | 说明 |
|---|---|
| 工作目录 | <路径> |
| 运行环境 | <版本、依赖> |
| 模型 | <模型名；接口地址写在哪> |
| 密钥 | <从哪里读；你不需要打开密钥文件> |
| 用量记录 | <trace 文件位置> |
| 断点续跑 | <中断后怎么继续> |

## 4. 规则
**不要做：**
- 不要输出、复制或提交密钥，也不要把密钥写进报告。
- 不要修改 <目录> 里已有的文件（例外见下）。
- 不要删除或覆盖已有结果；不要使用 `--fresh` 之类会清空结果的参数。
- 不要为了让指标变好而修改提示词、放宽校验或挑选样本。
- 不要把课件内容、题目或数据发到这台电脑以外的地方。
- 不要同时运行两个实验。

**脚本本身出错时：** 先用模拟模式复现；只做能让它跑起来的最小修改，只改 <允许修改的文件>；在报告里写明改了哪一行、为什么；改完跑一遍原有测试。

**模型输出不合格时：** 这是实验结果的一部分，照实记录，不要修。

**什么时候停下来问人：** 用量超过上限；连续 5 次调用失败或出现鉴权错误；需要修改允许范围之外的文件；<本机特有的情况，例：iCloud 读文件报错>。

## 5. 任务队列
开始前先确认原有测试通过：`<命令>`（不要用管道截断输出）。

### 任务 1：<名称>
- 为什么做：<一两句>
- 命令：先模拟，再真实模型
- 预估用量：<调用次数、token>；上限：<token>
- 产出：<文件>
- 要报告的数字：<从哪个文件照抄哪一部分>
- 判定（你不需要下结论）：<设计方会看什么>

## 6. 交回什么
在 <目录> 下写 `handoff-report-<日期>-r<n>.md`，不覆盖前几轮的报告：
- 运行时间、运行者（哪个 agent、哪个模型）
- 概况：每个任务完成 / 部分完成 / 没有运行，以及原因
- 每个任务：运行的命令、用量、照抄的结果数字、失败项、异常
- 对脚本的修改（没有就写“无”）
- 没有验证的事

写报告时：只写实际看到的，数字照抄不估算；区分“脚本说通过了”和“内容是对的”；不评价设计、不给后续建议；没跑成的任务也要写，附报错原文。

## 7. 给接手 agent 的提示词
（一段可以直接发给代跑 agent 的话：工作目录、先读本文件、遵守第 4 节、按顺序跑第 5 节、遇到停下来的情况立即停、按第 6 节交回。）
```
