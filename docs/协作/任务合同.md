# 任务合同模板

只用于大任务：跨会话、改接口合同或数据结构、同时涉及鸿蒙端和后端、描述含糊。小修沿用 AGENTS.md 的「默认完成标准」，不需要单独写合同。

合同写在任务开头，或写进 STATE.md 自己工作线的「当前步骤」。描述含糊时，先把合同给用户确认，再动手。

```markdown
# 任务合同
目标：      <一句话，要解决什么问题>
工作线：    <鸿蒙端 / 后端与 AI / 设计与评测>；分支：<harmony/…>
约束：      <不能改什么，例：不改 docs/接口合同/；不动鸿蒙工程>
交付物：    <例：任务分支上的提交 + PR + 实施记录>
完成标准：
  - <默认完成标准>
  - <本任务特有的可验证条件，例：上传 30 页 PDF 后，资料列表显示页数和版本判定>
  - <例：模拟器上竖屏截图无溢出，存 local/证据/>
需要批准：  <例：修改接口合同；新增依赖；合并 main>
遇阻时：    停下，把已尝试的方法写进 STATE.md「风险」，不要猜
```

## 写好“完成标准”的要点

- 每一条都能用命令、测试或截图验证。“体验更好”“代码更清晰”这种不行。
- 写清边界情况，比如空资料、超大文件、网络断开、模型输出不合格。
- 有现成的测试文件或合同样例时，直接写出路径。
