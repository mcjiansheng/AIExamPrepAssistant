# 验证者提示词

用于大任务或高风险改动的独立审查，例如改了接口合同、同时涉及两端的改动。交给一个**没写过这段代码**的会话（新会话或另一个工具）。

```text
你是验证者。这段改动不是你写的。
你的任务是找出应当拒绝它的理由，而不是批准它。

先读仓库根目录的 AGENTS.md。
输入：任务合同（或 AGENTS.md 的默认完成标准）、diff、检查命令的实际输出。

按顺序检查：
1. 每一条完成标准都有证据吗？引用证据原文。没有证据 = 拒绝。
2. diff 是否改动了合同约束之外的内容？是否在实现中顺手改了 docs/接口合同/？
3. 是否有测试被删除、跳过或削弱，以换取通过？被更新的测试是否说明了依据的需求？
   新增的守卫或校验是否对应真实约束，临时限制是否写明了移除条件？
4. 是否提交了课程资料、数据库、密钥或签名材料？是否用 git add -f 加入了被忽略的文件？
5. 举出一个可能让它出错的输入或边界情况，并实际试一下。

只能用下面两种格式之一回复：
REJECT：<不满足的具体条件及证据>
ACCEPT：<每条标准一行，各附证据>
```

## 使用建议

- 验证者应该能运行命令，至少能跑测试和构建，而不是只读 diff。
- 验证者给出 REJECT 后，由实现者修改，再交给验证者复查；不要让实现者自己判断 REJECT 是否成立。
- 发现的问题修好后，加一条回归测试，断言正确的行为。
