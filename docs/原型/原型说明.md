# AI 备考助手原型

> 代码目前位于 `~/Documents/软件工程/exam-prep-prototype`，因为测试用的课件也在“软件工程”文件夹里。本文件是那里 README 的副本。

验证三件事：能否用真实的课件和作业建立带权限和版本管理的知识库；能否用 LongCat 跑通“知识点 → 计划 → 出题”；以及只有一个模型时，能否靠工作流设计（信息隔离、程序验算、代码裁决）把题目质量做到可用。设计见`docs/设计/单一模型Agent工作流设计.md`。

## 快速开始

需要 Python 3.9 以上，查询、工作流和工作区界面只用标准库。

### 工作区界面

```bash
cd ~/Documents/软件工程/exam-prep-prototype
python3 ui/server.py
```

然后在浏览器打开 http://127.0.0.1:8765 。服务只监听本机，并拒绝其他网站发起的请求。

- **知识库：** 上传资料（PDF、PPTX、DOCX、TXT、MD），按个人、校内、共享三层查看当前用户能读到的资料，查看和确认版本判定，填写老师重点。切换到“演示”权限世界，可以用同学、外专业、外校用户的身份查看三级权限的效果。
- **Agent 工作流：** 启动建库、出题、回归评测或跨课程链接，实时查看各角色的工作：拓扑图中的圆点表示信息在角色之间传递；题目时间线显示每道题经过的检查、裁决和修订；点击可看每一版草稿、每项检查的结论和退回意见。
- **题库：** 复习计划和通过验证的题目，附出处、检查结论和提示；未通过的题单独列出。
- **回归评测：** 拦截率、误报率和每道题的检查结论，可勾选个别题重跑。

右上角的“模拟模型”不联网、不消耗额度，用来演示流程：每次调用会等待 0.3 到 1.5 秒，约三分之一的题第一版会故意写错一步，用来展示退回和修订。模拟结果不代表题目质量；模拟的回归评测结果单独保存在 `out/regression-mock/`。

上传 PDF 需要 `pdftotext`（`brew install poppler`）或 macOS 自带的 PDFKit（需要 Xcode 命令行工具）；PPTX 和 DOCX 在没有 python-pptx、python-docx 时用标准库解析；`.ppt` 需要 LibreOffice。界面会显示本机有哪些工具。

## 出题与验证组

出题 agent 输出结构化题目：解析拆成编号步骤，每步附资料原文；表格放在单独字段；计算题必须附验算代码和中间结果。之后同一个模型在相互隔离的上下文中做以下检查，最后由代码裁决：

| 检查 | 做法 | 只能看到 |
|---|---|---|
| V1 程序验算 | 在沙箱中运行出题方的验算代码，核对答案、中间结果和表格的每个数值 | 验算代码 |
| V2 盲解代码 | 独立写代码求解，再与标准答案和中间结果比较 | 题干、资料、中间量的名字 |
| V3 独立作答 | 低风险 1 次（不一致时补 2 次），中风险 2 次，高风险 3 次 | 题干、资料 |
| V4 逐步核对 | 每个步骤单独检查定义、公式、说法是否与资料一致 | 一个步骤和它引用的页 |
| V5 推导连贯 | 逐步检查能否由前面的步骤推出；另查是否遗漏必要步骤 | 题干、前面的步骤、资料 |
| V6 选项反驳 | 逐个尝试论证错误选项也正确，必须引用真实原文，再由独立判断确认；另查选项形式 | 题干、选项、资料 |
| V7 引用核对 | 代码核对引用原文是否真的出现在对应页 | 无需模型 |

- **风险分级：** 计算题、证明或推导题、附验算代码的题为高风险，简答为中风险，概念单选为低风险。
- **裁决：** 任何一项失败，就带着具体问题让出题 agent 修订，最多 2 次；仍失败就换同章节的另一个知识点重出。未通过的题保留在结果末尾，便于检查验证组。
- **沙箱：** 验算代码先做语法树检查，只允许少数数学相关标准库，禁止文件、反射和动态执行；然后在独立子进程中运行，有超时和资源上限。原型在本机运行，产品阶段应放进无网络的容器。
- **并发：** 默认同时处理 3 道题，每道题内部最多 3 个并发检查，即最多约 9 个并发请求。遇到限流会自动重试。

## 验证组回归评测

`data/regression/items.json` 是人工标注过的 34 道题：第二轮的 29 道原样导出（4 道有问题），加上按人工核对记录重建的第一轮 5 道问题题。第一轮另外 24 道正常题在用 `--fresh` 重新出题时被删除了，现在 `--fresh` 改为归档。

评测流程：旧格式题目先由模型**忠实转换**为结构化格式，代码会核对转换没有改动题干、答案、数值和表格，防止它顺手把错误改掉；然后运行验证组，与人工标注比较。结果写到 `out/regression/report.md`，包括拦截率、误报率、每题平均调用次数，以及每道题发现的问题。

**对因拦截：** 每道问题题在 `expected_checks` 中标注了能对因发现它的检查，只有这些检查判为失败才算“对因拦截”；其他检查判为失败记为“理由不对”。检查名对了理由也不一定对，报告里要人工抽查。

**稳定性：** 同一模型每次的判断会有波动。连续跑几轮完整评测（`--fresh` 会把上一轮结果归档），再运行 `python3 workflow/stability.py` 比较最近 3 轮，报告每轮成绩、结论一致的题的比例，以及各检查触发是否一致，结果在 `out/regression/stability.md`。

比较规则或检查改动后，可以用 `python3 workflow/regress.py --redo <题号> <题号>` 重跑指定的题，新结果覆盖旧结果。

**暂定目标：** 问题题至少拦下 70%，正常题误报不超过 3 道。误报的题要人工复看，有时是之前漏看的问题：2026-11-07 复看后，R2-商务智能-7 改标为有问题（解析引用课件时把“最小兴趣度”改成了“最小支持度”），现在是 10 道问题题、24 道正常题。复看结论记在每道题的 `review` 字段。

验证组的判定规则（2026-11-07 第三轮评测后调整）：

- **比较规则：** 写法不同但数值相同算一致（百分数、`f(5),e(9)` 与 `[5, 9]`、字典与列表），含 n 的表达式按取值比较（`n(2n−1)` 与 `2*n^2 - n`、`Θ(n²)` 与 `Θ(n^2)`）。
- **验算代码本身的问题：** 代码无法运行、缺中间结果、给不出答案，记为“未能验算”（error），不算题目有错；出题时仍会退回修好代码，回归评测中计入“未完成”。
- **V4 逐步核对：** 能看到题干条件，看不到答案和其他步骤；只有定义、公式、规则与资料意思相反才算矛盾；判为矛盾时独立复查一次，两次都确认才算失败，否则只提示。
- **V5 推导连贯和完整性：** 判为推不出或有遗漏时同样独立复查一次，两次都确认才算失败。
- **V2 盲解代码：** 答案和单个数值由代码直接比较；列表、序列、表达式等结构化结果写法常常不同，交给一次只看数学含义的判断（顺序无关的集合、总和与加数列表、非唯一的合法序列都算相同），确认不同才算失败。
- **V1 符号表达式：** 解析写的是含 n 的表达式、验算代码却代入具体数值时，记为“未能验算”。
- **V7 引用核对：** 引用被幻灯片上相邻文本框隔开、或公式在 PDF 文字层中顺序被打乱时，只提示不判失败。

## 重复和版本如何处理

模型不判断哪份是最终版。文件名可能误导，比如 `第三章 存储管理 2026.pdf` 的内嵌日期其实是 2024 年。流程是：

1. **按内容分组：** 比较文件哈希和每页文字，把完全相同、格式副本、修订版、空白模板与已填写版本归为一组。
2. **按证据判定：** 证据从强到弱是用户确认、文件内嵌修改日期或内容包含关系、文件名中的具体日期。文件系统修改时间会被同步改写，不采用；`.ppt` 转换后的日期也不采用。
3. **证据不足时问人：** 标记 `needs_confirmation`，暂用最可能的版本，并在结果中提示。用 `python3 kb/kb.py confirm-version <group_id> <material_id>` 确认。
4. **旧版不删除：** 检索和出题默认只用最终版。旧版可用 `--include-superseded` 查询并标记 `outdated`；最终版中没有对应内容的旧版页面会列出来。用户读不到最终版时才退回旧版，并给出提示。

## 当前范围和已知限制

- **收录范围：** 操作系统、商务智能、高级算法的全部课件和作业，共 42 份。未收录其他项目文件和教材影印版。
- **图片：** 课件逐页发给视觉模型转写，结果标注“由模型识别，未经核对”。作业里的图片尚未处理。
- **检索：** BM25 关键词检索，加模型整理的知识点和中英文术语。没有向量语义检索。
- **共享层：** 只有一份演示样例。真实统计信号至少需要 3 位贡献者，当前只有一位用户，所以没有实现聚合。
- **验证组：** 仍是同一个模型。程序验算能可靠发现计算和表格错误；概念类问题依赖信息隔离和原文约束，模型的系统性误解无法发现。
- **检索：** 出题仍使用固定规则选取的资料页，设计中的检索 agent 和证据包尚未实现。
- **排版：** 结果仍输出为 Markdown；结构化渲染、公式编译检查和 A/B 卷尚未实现。
- **工作区：** 同一时间只运行一个任务。上传的分享审核在原型中自动通过，权利依据仍按规则判定实际范围。重新运行 `kb/build_world.py` 会覆盖界面中登记的上传资料权限。停止任务时，正在进行的调用会先完成。
