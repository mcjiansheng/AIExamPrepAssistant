## 3. 关键机制

### 3.1 今天的任务怎么来

每天（或用户打开时）由服务端算出今日任务，规则写死在代码里，不交给模型：

1. 当天可用时间 = 用户设置的每日时间（可在今天页临时改，“今天只有 1 小时”）。
2. 按课程分配：离考试越近、未掌握的重点越多，分到越多。考前 2 天的课程优先级最高。
3. 每门课内的顺序：到期复习 → 昨天没做完的 → 计划里的新知识点（先学后练）→ 快练。
4. 每项任务带预计时长和“为什么排它”（一句话，点开才看）。

助手可以调整任务（“把高数挪到明天”），调整以卡片形式出现，可撤销。

### 3.2 掌握度

- 三态不变：未学、不稳、掌握。由作答结果决定（v2 规则），“懂了”只把未学改为“学过”，不直接算掌握。
- 新增记忆状态：答对后按 FSRS 思路计算下次到期日；考试日期之前的间隔按剩余天数压缩，保证考前每个重点至少复习一次。复习强度（轻松 / 标准 / 冲刺）对应目标保持率。
- 掌握度变化是全产品最重要的反馈，必须有动效（07）。

### 3.3 先出后核

v0 每道题核对完才给用户，一道计算题要等十几分钟。v1 改为：

1. 题目草稿生成后立即可作答，标“核对中”。
2. 核对在后台继续；通过则去掉标记；发现硬错误则在用户作答前替换，已作答则在解析处提示“这道题有问题，不计分”。
3. 快练和到期复习优先用题库里已核对过的题，题不够时才现出。

具体核对规则仍按 v2；服务端改造见 08。

断点沿用鸿蒙横向断点：xs < 320vp，sm 320–600，md 600–840，lg 840–1440，xl ≥ 1440。xl 只放宽内容，不新增布局。

### 4.3 课程内结构（取代 v0 的四步）

课程主页是一张“地图 + 下一步”，不再有资料 → 重点 → 计划 → 练习四个标签：

- 顶部：课程名、考试倒计时、准备度。
- 主体：知识点地图（按章节分块），点格子进知识点页。
- 侧边或下方：下一步（今天这门课的任务）、薄弱处、资料与重点入口、本课练习入口。
- 课程设置（考试日期、考试形式、每天给这门课的时间上限、删除课程）收在右上角菜单。

| 快练、错题、复习 | **主场景**：一题一屏 | 支持 | 支持 |
