# 04 · AI 接入与模型

## 1. 原则

1. **用户自带密钥。** 平台不提供模型额度（是否提供试用额度待定，见第 9 节）。
2. **在需要的地方都能接上。** 首次引导、设置、以及任何一个需要 AI 的操作当场，三处都能连接，不出现“功能不可用”的死路。
3. **密钥只进不出。** 填进去之后，任何客户端都拿不回明文。
4. **用的是用户的钱，就要算给用户看。** 大操作先估算，用量随时可查，可以设上限。
5. **能力不够时说清楚影响什么，并给补齐的办法。** 例如模型不能看图，就告诉用户“示意图不会被理解（图里的文字仍会识别）”，并给“添加看图模型”入口，而不是悄悄降级。
6. **基础识别不花用户的钱。** 文字识别和语音转文字由平台内置的开源模型或鸿蒙系统能力完成，免费、不需要密钥（第 4.3 节）。

## 2. 在哪里填

| 入口 | 时机 | 形式 |
|---|---|---|
| 首次引导 | 登录后、建第一门课之前 | 三步：选服务商 → 填密钥 → 检查连接。可以“先看看示例课程”跳过 |
| 设置 | 任何时候 | `我的 → AI 模型`：服务商、密钥、模型选择、用量、上限 |
| 当场 | 未连接时发起任何 AI 操作（发消息、上传资料、出题） | 弹出同样的三步弹层，连接成功后自动继续刚才的操作 |

### 2.1 首次引导的三步

**第 1 步 · 选服务商。** 先显示三四个大学生常用的服务商卡片（名称、一句话特点、大致价格档位），下面“更多服务商”和“自定义（OpenAI 兼容接口）”。不做“推荐”标签，避免替用户做商业选择；按名称排序。

**第 2 步 · 填密钥。** 一个输入框（粘贴即可），下方可展开“怎么获取密钥”：三步图文说明 + 服务商控制台链接。输入框下方一行告知：“课件和对话内容会发送给你选择的服务商处理。”（链接到资料处理说明）

**第 3 步 · 检查连接。** 自动进行，逐项打勾：

- 连接成功（发一次极小的请求）
- 拉取模型列表，按预设选好默认模型（用户可改）
- 能力检测（第 4 节），结果用“能做什么”的语言展示：
  - ✓ 对话和操作页面
  - ✓ 整理资料、出题
  - ✕ 看图：图里的文字仍会识别，示意图和流程图不会。可以再添加一个能看图的模型（第 4.3 节）。

失败时显示服务商返回的原因（“密钥无效”“余额不足”“该地区不可用”），停在第 2 步让用户改。

## 3. 服务商

### 3.1 预设

预设服务商只需填密钥。每个预设包含：名称、获取密钥的说明和链接、接口地址、协议类型、模型列表获取方式、各模型的已知能力和价格（价格可在设置里改）。

首批预设（按名称排序，开发时核实各家接口地址、模型名和价格）：

| 服务商 | 说明 |
|---|---|
| DeepSeek | OpenAI 兼容 |
| LongCat（美团） | 项目原型一直在用；OpenAI 兼容和 Responses 两种接口，现有实现已支持 |
| Kimi（月之暗面） | OpenAI 兼容 |
| 阿里云百炼（通义千问） | OpenAI 兼容 |
| 硅基流动 | 聚合多家开源模型，OpenAI 兼容 |
| 火山方舟（豆包） | OpenAI 兼容 |
| 智谱开放平台（GLM） | OpenAI 兼容 |
| 华为云 MaaS | 若接口兼容则加入；用户曾考虑用华为自身模型 |

### 3.2 自定义

- 协议：OpenAI 兼容（Chat Completions）；Anthropic 兼容（P1）。
- 填写：名称、接口地址、密钥、模型（可拉取列表，也可手填）。
- 地址规则沿用常见客户端的做法：填根地址时自动拼接标准路径；以 `#` 结尾表示完整地址、不拼接。界面上给一个示例。
- 本地模型（例如电脑上的 Ollama）只在“本机部署”时可用，因为服务端访问不到用户电脑上的地址。界面上对此做一句说明。

### 3.3 多个服务商

可以同时连接多个服务商（例如一个便宜的做对话，一个能看图的做资料识别）。一个服务商只存一把密钥（多密钥轮询不做）。

## 4. 模型角色与能力检测

### 4.1 四个角色

| 角色 | 用在哪里 | 需要的能力 |
|---|---|---|
| 对话 | 助手 | 工具调用（没有则退回 JSON 意图，v0 已实现）、流式输出 |
| 整理 | 资料抽取知识点、分析老师重点 | 长上下文、稳定的 JSON 输出 |
| 出题与核对 | 出题、解析、核对 | 推理能力、稳定的 JSON 输出 |
| 看图 | 课件图示转写、拍照资料、拍题 | 图片输入；主模型不能看图时可另加一个视觉模型（第 4.3 节） |

默认**一个模型担任全部角色**（符合用户最初“同一模型、合适的 agent 工作流”的设想）。`AI 模型 → 高级`里可以按角色指定不同模型。

### 4.2 能力检测

保存连接时检测，结果存起来，换模型时重测：

| 检测 | 方法 | 成本 |
|---|---|---|
| 连通与鉴权 | 一次极短的对话请求 | 几十 token |
| 模型列表 | 服务商的模型列表接口；没有则用预设 | 0 |
| JSON 输出 | 让模型返回一个固定小对象 | 几十 token |
| 工具调用 | 给一个无副作用的测试工具，看是否返回调用 | 约百 token |
| 看图 | 发一张很小的测试图，问上面的字 | 约几百 token |
| 上下文长度 | 来自预设或服务商元数据，不实测 | 0 |

检测结果决定功能是否可用，并在相关页面提示一次（例如资料页：“当前模型不能看图，示意图没有被理解。”带“添加看图模型”入口）。

### 4.3 识别能力：模型看不了图、听不了话怎么办

可以额外补上。识别分三种，前两种平台内置、免费、不需要密钥，第三种需要用户再加一个模型：

| 能力 | 用在哪里 | 默认做法 | 可选替换 |
|---|---|---|---|
| 文字识别（OCR） | 扫描版 PDF、课件图片里的字、拍照的笔记 / 板书 / 题目 | 服务端内置开源 OCR（RapidOCR），资料整理时自动运行。鸿蒙原生端拍照时先用系统 Core Vision Kit 在本机识别（离线、不联网、不需要密钥），把文字和原图一起上传 | 服务商的 OCR 或视觉模型 |
| 语音转文字 | 对话的语音输入、口述老师重点；P2 的录音转笔记 | 鸿蒙原生端用系统 Core Speech Kit（本机离线；中文普通话；短语音不超过 60 秒、长语音不超过 8 小时）。Web 端录音上传，由服务端内置开源模型转写（候选 SenseVoice-Small，CPU 可运行）。本版不启用，接口只预留，设置里显示“这一版暂未启用” | 服务商的语音识别接口 |
| 看图理解 | 示意图、流程图、表格结构、手写公式；拍题时理解题里的图 | 主模型能看图就用主模型；不能时，用户另加一个视觉模型，只担任“看图”角色 | — |

**没有看图模型时**：图片里的文字照常由 OCR 进入资料，图示本身标为“图示未解析”（v2 规则）；资料页提示一次，带“添加看图模型”入口。

**添加看图模型**：入口有三处——连接检查第 3 步的“✕ 看图”一行、资料页的提示、`设置 → AI 模型 → 看图`。流程同第 2.1 节，但服务商列表只显示有视觉模型的服务商，并预选它们的视觉模型（开发时核实各家视觉模型的名称和价格）。如果用户的主服务商本身就有视觉模型（同一把密钥），直接在列表里选，不用再填密钥。

**成本与隐私**：内置识别在我们的服务端或用户设备上运行，图片和录音不经过第三方，也不消耗用户的 token；代价是服务端多占 CPU 和内存，部署时单独评估。OCR 用的 RapidOCR 已于 2026-11-25 确认；语音识别的模型接入前再请用户确认。看图模型按用户的密钥计费，计入用量。

## 5. 用量、费用与上限

### 5.1 记录

每次模型调用记录：用户、课程、功能（对话 / 整理 / 出题 / 核对 / 看图 / 插件名）、服务商、模型、输入输出 token、是否成功、耗时。v0 的 `model-usage.jsonl` 改为数据库表（08）。

### 5.2 估算

服务商预设带价格表（每百万 token 输入 / 输出价格），用户可改。界面上同时显示 token 和估算金额，金额标“约”。

大操作开始前给出估算区间，依据是历史平均：

| 操作 | 估算依据 |
|---|---|
| 整理一份资料 | 按页数 |
| 出一套题 | 按题数和题型（计算题单独计） |
| 多步任务 | 各步之和 |

### 5.3 上限

- **单次确认阈值**：预计超过 2 万 token（可改）的操作，先出确认（对话里是提议卡，页面上是确认弹层），显示估算。
- **每日上限**（可选，默认关）：到达后 AI 操作暂停，次日恢复或手动提高；到 80% 时提醒一次。
- 后台任务在执行中到达上限：完成当前这一步后暂停，任务显示“已达今日上限”，可继续。

### 5.4 用量页

`我的 → AI 模型 → 用量`：本周 / 本月合计；按功能、按课程、按插件分列；最近的大额操作。图表用简单的条形图（07）。

## 6. 密钥的存储与安全

**存在服务端。** 原因：整理资料、出题、核对都是后台任务，要在用户关掉应用后继续跑；多设备登录后不用每台都重填。

| 要求 | 做法 |
|---|---|
| 加密存储 | 信封加密：服务端主密钥从环境变量或密钥管理服务读取，不进代码和数据库；每个用户一把数据密钥加密其服务商密钥 |
| 只写不读 | 接口只接收和替换密钥，从不返回明文；界面显示服务商名和末 4 位 |
| 最小使用 | 只在该用户自己的请求、后台任务、插件调用里解密使用，用完不缓存明文 |
| 不落日志 | 请求日志、错误信息、调用记录里都脱敏 |
| 传输 | 全程 HTTPS |
| 删除 | 删除连接立即失效；注销账号时一并删除 |
| 客户端 | 鸿蒙端输入密钥的输入框使用安全输入；客户端不保存密钥。若将来做“仅本机”模式，用鸿蒙关键资产存储（Asset Store Kit）保存 |
| 内置识别 | OCR 和语音转文字在本服务端或用户设备上运行，图片和录音不发给第三方 |

## 7. 失败处理

所有模型错误都转成“原因 + 下一步”，沿用 v0.1 的任务失败与重试机制：

| 错误 | 用户看到 | 下一步 |
|---|---|---|
| 401 / 403 | 密钥无效或没有权限 | 更新密钥（按钮直达） |
| 余额不足 | 服务商余额不足 | 去服务商充值（链接）；或换服务商 |
| 429 限流 | 服务商限流，稍后自动重试 | 自动退避；连续 5 次失败后任务失败，可重试 |
| 模型不存在 / 下线 | 模型不可用 | 从列表里换一个 |
| 网络或 5xx | 服务商暂时异常，稍后自动重试 | 同 429 |
| 内容审核拦截 | 服务商拒绝处理这段内容 | 说明是哪份资料或哪条消息；可跳过 |

## 8. 没连接时能做什么

- **示例课程**：内置一门预先生成好的课程（知识结构、讲解、题目都是静态数据），不调用模型，可以完整体验今天、学习、练习、结果。
- 自己的课程：可以建课、上传资料、设置考试日期；资料会显示“等待连接 AI 后整理”，连接后自动开始。

## 9. 平台托管试用额度（待定）

如果决定提供：新用户获得一小笔额度（平台出钱，用平台自己的密钥），用量页单独显示剩余；用完引导连接自己的密钥。服务端需要按用户限流和计费。本版不实现，数据模型里的“服务商连接”预留 `kind: platform` 一种类型。

## 10. 与现有实现的关系

- `server/model.py` 的 `LongCatClient` 改为“服务商连接”抽象：同一接口，按连接的协议类型（OpenAI 兼容 / LongCat Responses / Anthropic 兼容）发请求。密钥从数据库按用户解密，不再读 `local/api_key/`（本地开发仍可用环境变量覆盖）。
- `model-usage.jsonl` 改为用量表，字段见 08。
- 现有 `RetryLater` / `JobFailure` 与连续失败计数保留，错误文案按第 7 节统一。
- 资料整理流程加一步 OCR：页面没有文字层或含图片时先识别文字；有看图模型时再做图示转写（沿用 v0 的 `vision` 状态字段）。
