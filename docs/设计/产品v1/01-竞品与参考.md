# 01 · 竞品与参考

只记对我们有用的结论。每条写清：它做了什么、我们学什么、落到哪份文档。资料截至 2026-11。

## 1. 助学工具

### NotebookLM（Google）

- 做了什么：上传资料后生成学习指南、思维导图、闪卡、测验、音频 / 视频概览；所有内容只基于用户上传的资料，带出处。对话可切换成“Learning Guide”风格，用开放式提问引导用户自己想。测验做完可以针对答错的题再生成学习指南或闪卡。闪卡和测验可以设题量和难度。
- 学什么：
  - **只基于资料、处处有出处**是 AI 助学的信任来源。我们已有出处核对，要把它做成看得见的体验：点出处直接看课件原页并高亮引文（06 知识点页）。
  - **错题驱动下一轮学习**：答错的题直接生成针对性的复习（02 练习体系）。
  - **一份资料多种产出**：提纲、闪卡、测验、思维导图都从同一份知识结构出（02 P1 考前提纲）。
- 不学：它没有计划和掌握度，不知道你考试是哪天、哪里已经会了。这正是我们的位置。

### ChatGPT 学习模式 / Claude 学习模式 / Khanmigo

- 做了什么：学习模式不直接给答案，用苏格拉底式提问、提示和自我检查引导学生；可以基于记忆个性化；可在对话中随时开关。Khanmigo 的提示逐级加强，而且在学生做题时主动出现，不等学生问出“完美的问题”。
- 学什么：
  - **提示阶梯**：做题时求助分三级——方向提示 → 关键步骤提示 → 完整解析，最后一级才记“看过答案”（03 第 4 节）。
  - **在需要的时刻出现**：同一题停留过久或连续答错时，助手主动问一句要不要提示（03，可在设置里关）。
  - **模式可切换**：讲解默认引导式；用户说“直接告诉我”时切换为直接回答。
- 不学：通用聊天机器人的“万能输入框”首页。我们的首页先给今天的任务，对话入口常驻但不占满屏。

### Quizlet

- 做了什么：Learn 模式按掌握情况调整难度；“Study Bites”替用户选该用哪种学习模式；有闪卡、学习、测试、配对等模式；收购了把课堂录音变成笔记和测验的 Coconote；可在 ChatGPT 里直接调用 Quizlet 内容。
- 学什么：
  - **替用户选模式**：用户不该自己决定“现在刷闪卡还是做测验”，“今天”页按掌握度派任务（06 今天）。
  - **多种练习形态同一个题库**：快练、错题、到期复习、模拟卷共用题目和掌握度（02）。
- 不学：游戏化（积分、排行、对战）。期末复习的用户要的是效率，不是娱乐。

### Anki（FSRS 调度）

- 做了什么：FSRS 用“难度、稳定性、可提取性”描述每张卡的记忆状态，用户设一个目标记忆保持率，系统据此安排复习；比旧算法用更少的复习达到同样的记忆效果。
- 学什么：
  - **到期复习用 FSRS 思路**，但目标不同：我们有考试日期，要在考试那天的记忆保持率最高。复习间隔按“离考试的天数”压缩（02 练习体系，08 服务端）。
  - **一个参数控制强度**：设置里只给“复习强度：轻松 / 标准 / 冲刺”，背后对应目标保持率。
- 不学：手工制卡和复杂的卡组设置。

### 夸克（夸克老师、AI 解题）

- 做了什么：覆盖大量大学生；拍题、AI 搜题、分步讲解；“夸克老师”基于历史错题和知识点掌握程度做一对一辅导，推荐同类题，从“学会一道题”到“学会一类题”；与钉钉做了拍照批改和自动错题本。
- 学什么：
  - **拍照是手机上最自然的输入**：拍纸质笔记、板书、作业进资料；拍一道题问助手（03、05）。
  - **同类题**：错题本里每道题都能“再来一道同类的”（02）。
- 不学：以公共题库为中心。我们的题从你的资料出。

### 华为原生应用（日历、备忘录、健康、学习类元服务）

- 学什么：系统字体和图标、卡片化首页、服务卡片的多尺寸信息分级、平板分栏、电脑窗口化。转 ArkUI 时这些是零成本的“成熟感”（07）。

## 2. Agent 与 AI 客户端

### Cherry Studio / LobeChat 一类的 AI 客户端（自带密钥）

- 做了什么：设置里列出模型服务商；内置服务商只需填密钥；自定义服务商填 API 地址（自动拼接 `/v1/chat/completions` 一类路径，并有规则处理非标准路径）；可以一键拉取服务商的模型列表；一个服务商可填多个密钥轮询。
- 学什么（04）：
  - **服务商预设 + 自定义（OpenAI 兼容）**两层。预设填密钥即可，自定义才需要地址。
  - **保存时就验证**：发一次很小的请求，失败当场给出服务商返回的原因。
  - **拉取模型列表**，用户从列表里选，不手打模型名。
- 不学：把几十个服务商和参数全摆出来。我们只列国内大学生常用的几家，高级选项折叠。

### Dify（插件与模型供应商）

- 做了什么：模型供应商、工具、外部接口都是插件；插件在独立进程里运行，可以反向调用平台的模型和工具；保存凭据时调用验证方法，失败给出提示。
- 学什么（03、08）：
  - **插件与主服务隔离运行**，崩溃或超时不影响主流程。
  - **插件可以反向调用**我们的能力（取课件页、出题、读掌握度），但都要经过权限声明。

### Agent Skills（SKILL.md 开放格式）与 MCP

- Agent Skills：一个技能是一个文件夹，`SKILL.md` 里有名称、描述和操作说明，可附脚本、参考资料、模板。agent 启动时只读名称和描述，任务相关时才读全文，再按需读附件——“渐进披露”，上下文成本低。格式已作为开放标准发布，多个 agent 产品支持。
- MCP：标准的工具协议。服务器可以提供三类东西：工具（模型决定调用）、资源（应用决定附带的上下文）、提示模板（用户主动选用，常做成斜杠命令）。
- 学什么（03）：
  - **插件 = 技能（SKILL.md）+ 工具（MCP）+ 可选的界面卡片和题型。**直接兼容这两个格式，社区现成的技能和工具可以用，团队成员用别的 agent 写的技能也能拿来。
  - **渐进披露对自带密钥的用户尤其重要**：装了十个插件，平时只花十几行描述的 token。
  - **三种控制方式对应三种界面**：工具由助手调用（带确认级别）；资源是“@ 引用”（@某门课、@某份资料）；提示模板是“/ 命令”（/出题、/讲解）。

### Cursor、Notion AI、Copilot 一类的“侧栏助手”

- 学什么：大屏上助手常驻在侧栏，**自动知道你正在看什么**（当前课程、知识点、题目），引用当前内容不需要复制粘贴；助手的修改直接落到页面上，并能撤销（03、06）。

### 小艺与 HarmonyOS 意图框架

- 做了什么：应用通过意图框架（Intents Kit）把能力注册给系统，用户对小艺说一句话、在搜索里搜，就能直达应用的某个页面或功能；2026 年小艺升级为 agent 架构。
- 学什么（05）：原生版把几个高频动作注册成意图——“今天复习什么”“出 5 道操作系统的题”“离高数考试还有几天”。这是鸿蒙独有的“多入口”，P2 实现，现在定好意图清单。

## 3. 汇总：我们取什么

| 来源 | 取 | 落点 |
|---|---|---|
| NotebookLM | 只基于资料、点出处看原页；错题生成下一轮复习 | 02、06 |
| 学习模式 / Khanmigo | 提示阶梯；卡住时主动出现；引导与直答可切换 | 03 |
| Quizlet | 系统替用户选学习模式 | 02、06 |
| Anki FSRS | 到期复习，按考试日期压缩间隔；一个“强度”参数 | 02、08 |
| 夸克 | 拍照输入；同类题 | 02、03、05 |
| Cherry Studio | 服务商预设 + 自定义、保存即验证、拉取模型列表 | 04 |
| Dify | 插件隔离运行、反向调用需声明权限 | 03、08 |
| Agent Skills / MCP | 插件格式；渐进披露；@ 资源与 / 命令 | 03 |
| 侧栏助手 | 大屏常驻、自动带上下文、改动可撤销 | 03、06 |
| 鸿蒙 | 系统设计语言、服务卡片、意图框架、一键登录、关键资产存储 | 05、07 |
