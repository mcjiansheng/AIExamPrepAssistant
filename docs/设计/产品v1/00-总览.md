## 1. 产品定位

**满格：一个懂你课件的备考 agent。** 大学生把课件、作业、老师划的重点交给它，它整理出这门课考什么、排好几门课的复习时间，陪你一个知识点一个知识点地学懂、练会，并随时知道你还差什么。

一句话区别：

- 和“拍题搜题”（夸克、作业帮）比：我们围绕**你这门课的资料和老师的重点**，不是公共题库。
- 和“通用 AI 对话”（ChatGPT、豆包）比：我们有**课程结构、掌握度和计划**，对话能直接改它们，结果长期保存。
- 和“闪卡 / 刷题”（Anki、Quizlet）比：题目和讲解**从你的资料自动生成并标出处**，计划跟着掌握度自动调整。

## 2. 用户与场景

主要用户：期末周的大学生。两周内考四五门；资料多、时间少、不知道重点、不知道自己哪里不会。

| 场景 | 设备 | 用户想要 |
|---|---|---|
| 早上 / 课间打开 | 手机 | 今天学什么，离考试还有几天；碎片时间刷几道题 |
| 晚上坐下来系统复习 | 平板 / 电脑 | 对着课件学懂一个主题，做一套模拟卷 |
| 刚拿到资料 / 老师划完重点 | 电脑 / 手机拍照 | 把资料和重点交给它，别让我整理 |
| 学不进去 / 卡住了 | 任意 | 直接问：“这个到底什么意思”“我只剩三天怎么办” |
| 考前一晚 | 手机 / 打印 | 一页提纲，过一遍重点和错题 |

## 3. 核心循环

```
准备（一次）          每天（循环）                         复盘
上传资料 ─┐      ┌─→ 今天：系统按时间和掌握度派任务 ──┐
老师重点 ─┼─→ 课程结构 + 计划    学：知识点页 / 问助手        │ 掌握度变化
考试日期 ─┘      │   练：快练 / 错题 / 到期复习 / 模拟卷 ←┘ 计划自动顺延
                 └──────────── 对话贯穿每一步 ──────────────┘
```

## 4. 设计原则

1. **以“今天”为中心。** 首页回答“现在做什么”，跨所有课程。
2. **对话是一等入口。** 页面上能做的事，说一句话也能做；说一句话能做的，很多页面上一步做不到（“把操作系统挪到周末，周三考的那门先排”）。对话结果以卡片形式出现，可执行、可撤销、可保存。见 03。
3. **准备只做一次。** 新建课程走一次引导，之后整理在后台进行，设置收进课程设置。
4. **系统替用户判断，留撤销。** 只有会长期影响结果的设置（考试形式）和不可逆操作（删除）才问。
5. **一切出自资料。** 讲解、题目、提纲都标出处，点出处能看到课件原页。资料里没有的，明说没有。
6. **掌握度是视觉主线。** 用“知识点地图”贯穿首页、课程、学习、结果。见 07。
7. **每种设备做适合它的事。** 见 02 第 5 节。
8. **成本透明。** 用户自带密钥，花的是自己的钱：大操作先估算，随时能看用量。见 04。
9. **文字只做标签。** 不写解释性副标题，不暴露流水线概念。

## 5. 已定决定

| 决定 | 理由 / 来源 |
|---|---|
| 最终形态是鸿蒙原生 ArkUI，手机、平板、电脑各做适合的功能 | 用户决定 |
| 没有设备测试，先用 Web 做设计和实现蓝本，再由 AI 转 ArkUI | 用户决定 |
| Web 前端用 TypeScript + React + Vite | 用户同意；ArkTS 基于 TypeScript，声明式组件便于转换 |
| 本版只做个人端，课程共享（三级知识的课程 / 校内层）下一版做；数据模型先留位置 | 用户决定 |
| 账号：手机号 + 验证码；鸿蒙端华为账号一键登录。本版先做设计和接口，一键登录不必完整实现 | 用户决定 |
| AI 由用户自带密钥接入，密钥存在服务端（加密），不返回给客户端 | 04 |
| 对话是核心交互，插件扩展 agent 能力；插件格式兼容 Agent Skills（SKILL.md）和 MCP | 用户决定方向；格式选择见 03 |
| 视觉按 HarmonyOS 设计规范，个性来自知识点地图和动效 | 07 |
| 出题采用“先出后核”：题目先给用户，核对在后台进行 | 02、08；解决出题慢 |
| 产品名「满格」，英文 Fullgrid | 知识点地图的格子全部点亮就是复习到位，也取“状态满格”的意思；见 07 第 9 节。上架前核查商标和应用市场重名 |
| 文字识别、语音转文字由平台内置（服务端开源模型；鸿蒙端用系统能力），免费；看图理解可另加一个视觉模型 | 用户问到模型不能识图 / 语音时怎么办；见 04 第 4.3 节 |
