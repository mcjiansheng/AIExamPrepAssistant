# 10 · 前端设计逻辑与交互准则

状态：v1 细节设计，2026-11-25（PST）。06 写每页有什么，07 写长什么样，本文写**为什么这样排、交互守哪些规矩、前端代码怎么组织**。`client/` 的实现和评审都对照本文。

## 1. 五个要求怎么落到界面

| 要求 | 落到界面上 | 怎么检查 |
|---|---|---|
| 清晰 | 每页只回答一个问题（第 2 节）；一页一个实心主按钮；状态同时用形状和颜色 | 看截图 3 秒内能指出主按钮和当前状态 |
| 简洁 | 文字只做标签；说明最多一行；能用数字和图形就不用句子 | 没有解释性副标题；除讲解和题目外，没有超过两行的段落 |
| 美观 | 鸿蒙质感：系统字体、底色与白色容器分层、卡片不加阴影、大号数字、知识点地图是唯一的装饰 | 样式里没有 token 之外的颜色和间距 |
| 流畅 | 点击 100ms 内有按下态；可撤销的操作先改界面再等服务端；只在状态变化时动 | 端到端测试量反馈时间；“减少动态效果”开关生效 |
| 直观 | 名词标题、动词按钮、前后用同一个动词；点开即开始 | 第 6 节的动作文案表 |

## 2. 每页回答一个问题

| 页面 | 回答的问题 | 主操作 | 次要操作 |
|---|---|---|---|
| 今天 | 现在做什么 | 第一项没做的任务（整张卡可点） | 勾选、挪到明天、调整今天的时间 |
| 课程列表 | 每门课还差多少 | 新建课程 | 卡片菜单 |
| 课程主页 | 还差多少、下一步做什么 | 下一步的第一项 | 资料、老师重点、练习、学情 |
| 知识点 | 懂了没有 | 懂了 | 讲简单点、举个例子、考考我；上一个 / 下一个 |
| 资料 | 资料齐了没、读对了没 | 添加资料 | 改类型、删除 |
| 老师重点 | 老师说的落到了哪些知识点 | 添加原话 | 选入 / 移除、考试形式 |
| 日程 | 这几天怎么排 | 直接拖动 | 每日时间、复习强度、重排 |
| 练习 | 现在练什么 | 开始快练 | 到期复习、错题本、模拟卷 |
| 作答 | 这道题怎么做 | 提交 → 下一题 | 求助、报错 |
| 结果 | 变了什么、接下来做什么 | 按建议开始 | 回看错题、回到今天 |
| 学情 | 来得及吗 | — | 薄弱知识点 |
| 我的 | 设置在哪 | — | 分组列表 |

**排版顺序**：页面自上而下 = 结论（大号数字或地图）→ 现在要做的事 → 其他入口。用户不滚动就能看到结论和主操作。

## 3. 人机交互准则

| 编号 | 准则 | 具体做法 |
|---|---|---|
| H1 | 一页一个主按钮 | 主按钮是实心胶囊；其余用次按钮（浅色填充）或文字按钮 |
| H2 | 名词标题、动词按钮 | 按钮 2–6 个字，动词开头；完成提示用同一个动词（“开始快练” → “快练完成”） |
| H3 | 文字只做标签 | 不写解释性副标题；新概念第一次出现时用一次性气泡说明；原因和细节放在点开之后（任务的“为什么排它”、资料的判断依据） |
| H4 | 先做后撤 | 可撤销的直接执行，底部撤销条 5 秒；只有不可逆（删除、注销）和长期影响（考试形式、考试日期）的才确认，确认框写清会失去什么 |
| H5 | 点开即开始 | 任务卡、练习入口、地图格子点一下就进入要做的事，没有中间确认页；模拟卷例外，先看题量、时长和用量估算 |
| H6 | 等待有分寸 | 按下 100ms 内有按下态；300ms 内没结果显示与真实布局同形的骨架；3 秒仍未完成加一行“正在做什么”；预计超过 30 秒转后台，页面内显示进度，可以离开，完成通知；不用全屏遮罩 |
| H7 | 没有死路 | 错误 = 原因 + 下一步按钮；空状态 = 一句话 + 一个主按钮；需要 AI 但没连接 → 当场连接，连接后自动继续 |
| H8 | 状态不只靠颜色 | 掌握度用形状区分（空心、带点、半格、满格）；对错配图标；图标按钮都有可读名称 |
| H9 | 回到原处 | 返回时恢复滚动位置、题号、页码；跨设备用“继续”卡片 |
| H10 | 页面和助手是同一份数据 | 助手改了什么，页面上那一块高亮一次，撤销在卡片上 |
| H11 | 动效只表达变化 | 全产品只有欢迎页一处进场动画；交互用弹簧；尊重“减少动态效果” |
| H12 | 设备各做擅长的事 | 手机主操作放在下半屏，单手可达；平板和电脑用分栏，不拉长行宽（讲解每行不超过 38 个汉字） |
| H13 | 可达性 | 点击区域不小于 44×44；键盘能走完主流程，焦点环可见；地图格子有读屏文字；对比度达标（07 第 2.4 节） |
| H14 | 花钱要说 | 预计超过阈值的 AI 操作先给估算；用量随时可查 |
| H15 | 出处可信 | 讲解和题目都带出处，点开看原页；“核对中”“未经核对”如实标出；失败就说失败 |
| H16 | 不打扰 | 主动出现只有三处（每日简报、考后复盘、卡住时），都能关；不用表情和感叹号 |

## 4. 布局系统

### 4.1 外壳

| 断点 | 宽度（vp） | 主导航 | 助手 | 详情页 |
|---|---|---|---|---|
| sm（含 xs） | < 600 | 底部标签栏：今天 · 课程 · 练习 · 我的 | 主页面底部的输入条；点开为底部弹层（半屏 → 全屏） | 推入新页面 |
| md | 600–839 | 左侧窄栏 80（图标 + 文字） | 右侧抽屉 360；收起时是一条细边 | 主从双栏 |
| lg | 840–1439 | 左侧窄栏 80，主导航下方是课程色点 | 右侧常驻面板 340，可收起 | 双栏 |
| xl | ≥ 1440 | 左侧栏 248：主导航 + 课程列表（名称、倒计时） | 右侧常驻面板 380 | 三栏，内容区限宽 |

lg 用窄栏而不用整条侧栏：840 宽时侧栏 248 加助手 340 只剩 252 给内容。课程列表在窄栏里以课程色点出现（悬停显示名称），到 xl 再展开成整条侧栏。这是对 02 第 4.2 节的细化，结构不变。

### 4.2 页面骨架

- 页头：一级页面是大标题（24/32 Bold）；推入的页面是“返回 + 标题 + 右侧图标按钮”。
- 内容：页边距 sm 16、md 24、lg 32；分组容器白底圆角 20，组与组间距 24。
- 手机底部：主页面是助手输入条（标签栏上方）；作答页是“求助 + 提交”。

### 4.3 作答页

全屏，不显示主导航。手机一题一屏；平板、电脑上的模拟卷是整卷模式：左题号格、中间题目、右侧助手或草稿区。快练、复习在任何设备上都是单题模式。

## 5. 组件状态

每个可交互组件都有：默认、悬停（指针设备）、按下（缩到 0.97，M8）、键盘焦点（2px 强调色环，外偏 2px）、禁用（文字 38% 透明度，不可点）、加载中（按钮宽度不变，图标位换成转圈）。

| 组件 | 规则 |
|---|---|
| 主按钮 | 高 40（手机底部操作区 48），胶囊形；同一屏最多一个 |
| 列表项 | 最小高 56；整行可点；右侧值或箭头 |
| 撤销条 | 底部居中，5 秒，带剩余时间细线；新的撤销条替换旧的 |
| 弹层 | 手机为底部弹层，可拖到全屏；平板和电脑为居中对话框或侧边抽屉 |
| 确认框 | 只用于不可逆操作；标题写动作和对象（“删除《第三章课件》？”），正文一行写后果，危险按钮用红色 |
| 骨架 | 与真实布局同形，1.5 秒周期微光；减少动态效果时不闪 |
| 空状态 | 一句话 + 一个主按钮，不放插画 |
| 错误状态 | 原因 + 下一步按钮（重试、去设置、重新上传） |

## 6. 动作文案

| 动作 | 按钮 / 入口 | 完成后 |
|---|---|---|
| 勾掉任务 | 任务卡右侧的圆圈 | 撤销条“已完成 · 撤销” |
| 挪到明天 | 任务菜单“挪到明天” | “已挪到明天 · 撤销” |
| 跳过任务 | 任务菜单“跳过” | “已跳过 · 撤销” |
| 开始快练 | “开始快练” | 结果页标题“快练完成” |
| 交卷 | “交卷” | 结果页标题“模拟卷完成” |
| 学懂一个知识点 | “懂了” | 地图格子变化，进入下一个 |
| 提交答案 | “提交” | “答对了” / “答错了” + 解析 |
| 添加资料 | “添加资料” | “已添加 3 份，正在整理” |

| 调整今天的时间 | “调整” | 任务重排（M6） |

## 7. 动效落点

| 编号 | 用在哪里 | Web 实现 |
|---|---|---|
| M1 | 课程卡 → 课程主页；任务卡 → 知识点页 | View Transitions API，源和目标设同一个 `view-transition-name`；不支持时淡入淡出 |
| M2 | 勾掉任务 | 勾的描边画出 → 卡片高度收起移入“已完成” → 进度环增长 |
| M3 | 提交答案 | 答对放大回弹 + 绿；答错水平抖动 + 红；页头小地图对应格子同时变色 |
| M4 | 结果页、从结果回到课程 | 变化的格子依次放大变色（间隔 40ms），得分从 0 滚到实际值 |
| M5 | 整理资料、出题 | 骨架格子和题号格微光，完成一项亮起一项 |
| M6 | 顺延、助手改日程、拖动 | FLIP：记下旧位置，换数据后从旧位置弹簧移动到新位置，背景高亮 1 秒 |
| M7 | 助手弹层；助手执行动作后 | 弹层弹簧上滑；页面上被改的区域高亮一次 |
| M8 | 按下 | 缩到 0.97，松开回弹 |

弹簧用 CSS `linear()` 采样实现，参数取自 07 第 7.1 节的 `spring.default` 和 `spring.bouncy`，由 token 生成脚本计算。“减少动态效果”开启时，所有位移、缩放、抖动改为 150ms 淡入淡出，数字直接显示终值。

## 8. 前端架构

### 8.1 分层

```
tokens → layout（布局原语）→ ui（展示组件）→ features（领域组件 + 数据 hooks）→ pages（路由入口）
```

- `ui/` 不取数据，只接 props。`features/` 通过 `api/` 的 hooks 取数据。`pages/` 只组合，不写样式。
- 业务代码不写 `div` 加样式，只用布局原语和 `ui/` 组件（08 第 1.3 节）。

### 8.2 数据流

| 场景 | 做法 |
|---|---|
| 读 | TanStack Query，按资源分键：`today`、`schedule`、`courses`、`course/{cid}`、`kp/{kid}`、`session/{sid}` 等 |
| 写 | mutation 返回的 `affects` 决定失效哪些键；服务端事件流（SSE）同样按 `affects` 失效 |
| 可撤销的写 | 乐观更新，失败回滚并提示原因；成功后显示撤销条，撤销走 `POST /undo/{id}` |
| 对话 | 流式读取消息事件，逐段渲染；卡片带 `affects`，渲染时顺带失效对应页面 |
| 位置 | 打开知识点、翻到某题时上报 `PUT /me/resume`，“继续”卡片据此显示 |

### 8.3 统一拦截

| 响应 | 客户端 |
|---|---|
| 401 | 用刷新令牌换一次，成功后重发；失败回到登录页 |
| 403 `login_required` | 访客要保存数据：弹登录层，登录后重发 |
| 409 `ai_required` | 弹连接 AI 层，连接后用同一个幂等键重发 |
| 409 `needs_confirmation` | 弹确认，显示用量估算；确认后带 `confirm: true` 重发 |
| Job `needs_input` 带 `estimate` | 后台任务等确认用量（如整理资料）：刚上传时弹同一个估算，确认后 `POST /jobs/{id}/continue`；没当场确认的，课程主页和资料页给“开始整理” |
| 网络失败 | 顶部“离线”细条；读请求显示缓存；写请求保留在原处并给“重试” |
| 其他错误 | 原因 + 下一步（服务端的 `message` 已是给人看的话） |

### 8.4 演示后端

`src/mock/` 在浏览器里按 `api-v1.md` 实现全部接口：示例课程、模拟的整理进度、流式的助手回复。找不到后端或地址带 `?api=mock` 时启用；数据存在 localStorage，`我的 → 数据` 里可以重置。它是每个接口的可运行样例，后端可以对照它的返回形状。

### 8.5 其他约定

- 断点：`useBreakpoint()` 返回 `xs | sm | md | lg | xl`，阈值 320 / 600 / 840 / 1440；布局分支只看这个值。
- 文案：全部在 `strings/zh-CN.ts`。
- 图标：lucide-react，统一 1.5 线宽，通过 `Icon` 组件按语义名取用；`ui/icons.ts` 维护“语义名 ↔ lucide ↔ HM Symbol”对照表。
- 转 ArkUI 的约束见 08 第 1.3 节。

## 9. 验收

- **尺寸**：390×844（sm 手机）、768×1024（md 平板竖屏）、1280×800（lg 平板横屏 / 笔记本）、1600×1000（xl）。
- **端到端流程**（Playwright，用本机 Chrome）：
  1. 看示例 → 今天 → 学一个知识点 → 快练 5 题 → 结果；
  2. 登录 → 连接 AI → 新建课程 → 上传资料 → 整理完成；
  3. 助手“把操作系统挪到明天” → 今天页更新 → 撤销。
- **截图**：每个 P0 页面在四种尺寸下各一张，供设计评审；视觉通过后再把它们设为截图回归的基准。
- **可达性**：主流程只用键盘能走完；地图格子能被读屏读出；浅色、深色两套配色的对比度达标。
