# 08 · 工程与服务端

本文给开发 agent 用：前端怎么搭才能顺利转 ArkUI，服务端要补哪些能力，接口 v1 的大纲，以及建议的分工顺序。接口合同 v1 的正文按 AGENTS.md 单独提 PR，本文只给大纲。

项目规约照旧：**拒绝过度防御性编程，拒绝非必要门控，拒绝无脑“拒绝”导致错误而不进行处理。**

## 1. 前端

### 1.1 技术栈

| 用途 | 选择 | 说明 |
|---|---|---|
| 语言 | TypeScript（strict） | ArkTS 基于 TypeScript，类型、模型、接口代码可直接搬 |
| 界面 | React | 声明式组件，对应 ArkUI 的 `@Component` + `build()` |
| 构建 | Vite | |
| 路由 | React Router | 路由按“页面栈”使用，见 1.3 |
| 服务端数据 | TanStack Query | 缓存、失效、离线读取 |
| 客户端状态 | Zustand | 小而集中，对应 `AppStorage` |
| 测试 | Vitest（单元）、Playwright（三种尺寸的端到端与截图） | |

用户已同意 TypeScript + React + Vite。表中其余库（路由、数据、状态、测试）同属新增依赖，开发前列清单请用户确认一次。可评估华为提供的 H5 一多布局库（`@hadss/web_adaptive_layout_react`），用了能让断点和响应式行为与鸿蒙一致。

新前端放在 `client/`，与旧的 `web/` 并存；新前端达到 P0 后再删除 `web/`（删除前问用户）。

### 1.2 目录

```
client/
  src/
    tokens/        设计 token（tokens.json）→ 生成 CSS 变量；同一份生成鸿蒙 resources
    ui/            基础组件：每个文件一个组件，对应一个 ArkUI 组件或自定义组件
    layout/        Row / Column / Stack / GridRow / GridCol / List / Navigation 等布局原语
    features/      按功能分：today、course、kp、materials、focus、schedule、practice、
                   session、result、insight、assistant、settings、auth、onboarding、plugins
    pages/         路由入口，一页一个文件（对应 NavDestination）
    api/           按接口合同 v1 生成的类型和请求函数
    mock/          演示后端：实现接口合同，演示数据，供开发和“示例课程”截图
    state/         全局状态（用户、断点、偏好）
    strings/       全部界面文案（zh-CN），对应鸿蒙 string 资源
  tests/
```

### 1.3 为转 ArkUI 定的规矩

1. **组件只用布局原语和 `ui/` 组件拼**，不在业务代码里直接写 `div` 加样式。布局原语的名字和参数对齐 ArkUI（`Row`、`Column`、`Stack`、`GridRow`、`GridCol`、`List`、`ListItem`），转换时几乎逐行替换。
2. **样式只引用 token**，不出现裸颜色、裸数值。
3. **一个页面文件 = 一个 NavDestination**；页面之间跳转用 `navigate` 封装成“push / pop / replace”，不依赖浏览器特有的行为。
4. **断点**：`useBreakpoint()` 返回 `xs | sm | md | lg | xl`，阈值与鸿蒙一致（320 / 600 / 840 / 1440 vp）；布局分支只看这个值。
5. **状态**：组件内状态用 `useState`；跨组件用 store；服务端数据用 Query。不在组件里直接 `fetch`。
6. **动效**：只用 07 的动效 token；共享元素过渡用 View Transitions API（不支持时退化为淡入淡出）。
7. **文案**全部从 `strings/` 取。
8. **无障碍**：所有可交互元素有可读名称；焦点环可见；尊重减少动态效果。

### 1.4 React ↔ ArkUI 对应

| Web | 鸿蒙 |
|---|---|
| 页面组件 | `NavDestination` |
| 路由栈 | `Navigation` + `NavPathStack` |
| 函数组件 | `@ComponentV2 struct` + `build()` |
| props | `@Param` |
| `useState` | `@Local` |
| store（Zustand） | `AppStorageV2` / `@ObservedV2` 类 |
| `useEffect` 挂载 | `aboutToAppear` |
| 断点 hook | 断点监听（`BreakpointSystem` 或窗口尺寸回调） |
| tokens → CSS 变量 | `resources/base/element/*.json` + `$r()` |
| `fetch` / 流式响应 | `@kit.NetworkKit` 的 `http`（流式用 `requestInStream`） |
| SSE 事件流 | `http` 流式读取或 WebSocket（转换时定） |
| `localStorage` 缓存 | Preferences / 关系型数据库 |
| 文件上传 | `DocumentViewPicker`、`PhotoViewPicker`、相机 |
| 录音上传后服务端转写 | Core Speech Kit `speechRecognizer`（本机离线） |
| 拍照上传后服务端 OCR | Core Vision Kit `textRecognition`（本机离线），文字与原图一起上传 |
| 浏览器通知 | Notification Kit；定时提醒用 `reminderAgentManager` |
| 动效 token | `curves.springMotion`、`animateTo`、`geometryTransition` |

## 2. 服务端

### 2.1 栈

v0 用 Python 标准库 HTTP 服务和 SQLite，适合单人本机。v1 要多用户、事件流、可部署，建议：

| 用途 | 建议 |
|---|---|
| Web 框架 | FastAPI + Uvicorn |
| 数据库 | PostgreSQL（开发可继续用 SQLite），迁移用 Alembic |
| 文件 | 开发用本地目录；生产用兼容 S3 的对象存储 |
| 后台任务 | 保留 v0 的持久化任务表 + 独立 worker 进程（重试、退避、连续失败计数已验证过） |
| 插件运行时 | 独立进程，MCP 客户端连接各插件 |
| 内置识别 | OCR 候选 RapidOCR / PaddleOCR；语音转文字候选 SenseVoice-Small（FunASR）；均在服务端 CPU 运行 |
| 部署 | Docker：api、worker、plugin-runtime 三个服务 + 数据库；配置全走环境变量 |

这些是新增依赖，开发前列清单请用户确认。AI 流程（`server/workflow/`、`server/kb/`）的逻辑原样迁移，不重写。

### 2.4 先出后核

题目状态：`drafted`（可作答，标核对中）→ `verified` / `replaced` / `flagged`。

- 草稿生成后立即推给客户端。
- 核对按 v2 规则在后台跑；硬错误时：未作答 → 替换为新题；已作答 → 标记 `flagged`，不计分，解析处说明。
- 快练、复习优先从该用户已核对的题库取题；不够再现出。
- 计算题仍走“先算后写”，作为内置插件（03 第 8.8 节）。

### 2.5 安全

- 每个接口按 `user_id` 校验资源归属；插件调用同样经过归属校验和权限校验。
- 限流：短信（每号每分钟 1 次、每天 10 次）、登录尝试、对话请求。
- 密钥：见 04 第 6 节。
- 资料和插件返回内容一律作为数据传给模型，不作为指令（v0 已有此规则）。
- 上传：类型白名单、大小上限，与 v0 一致。

## 3. 接口 v1 大纲

前缀 `/api/v1`。认证用 `Authorization: Bearer`。错误格式沿用 v0。

| 组 | 接口 |
|---|---|
| 认证 | `POST /auth/sms`、`POST /auth/login`（手机号 + 验证码）、`POST /auth/huawei`（授权码）、`POST /auth/qr`（生成）、`GET /auth/qr/{id}`（轮询）、`POST /auth/qr/{id}/confirm`（手机确认）、`POST /auth/refresh`、`POST /auth/logout` |
| 我 | `GET/PATCH /me`、`GET /me/devices`、`DELETE /me/devices/{id}`、`POST /me/export`、`DELETE /me` |
| 模型 | `GET /providers/presets`、`GET/POST /me/providers`、`PATCH/DELETE /me/providers/{id}`、`POST /me/providers/{id}/check`、`GET /me/usage`、`PUT /me/limits`、`POST /estimate` |
| 今天与日程 | `GET /today`、`PATCH /today`（今日可用时间）、`GET /schedule`、`PATCH /schedule/items/{id}`（挪动、跳过、固定） |
| 课程 | v0 的课程、资料、知识结构、重点、考试形式接口迁移到 v1，加归属；`GET /courses/{cid}/map`（知识点地图数据） |
| 学习 | `GET /kps/{kid}`（讲解、出处、怎么考、小测）、`POST /kps/{kid}/understood` |
| 练习 | `POST /sessions`（kind、course、kp、count）、`GET /sessions/{sid}`、`POST /questions/{qid}/attempt`、`POST /questions/{qid}/hint`（level）、`POST /questions/{qid}/report`、`POST /sessions/{sid}/finish`、`GET /mistakes`、`POST /mistakes/{qid}/similar` |
| 学情 | `GET /courses/{cid}/insight` |
| 对话 | `GET/POST /threads`、`GET /threads/{tid}`、`POST /threads/{tid}/messages`（流式响应，事件含文字、工具、卡片、提议、任务）、`POST /cards/{id}/undo`、`POST /proposals/{id}`、`POST /tasks/{id}/stop`、`GET/DELETE /me/memory` |
| 插件 | `GET /plugins`、`POST /plugins`（安装：文件或链接）、`PATCH /plugins/{id}`（启用、课程、权限）、`DELETE /plugins/{id}` |
| 事件 | `GET /events`（SSE：任务进度、跨设备改动、通知） |
| 通知 | `GET /notifications`、`POST /notifications/read`、`PUT /me/reminders` |
| 识别 | `POST /speech/transcribe`（Web 语音输入，上传录音返回文字）；文字识别在资料整理和拍照上传时由服务端自动完成，不单独开放 |
