# 03 · 助手与插件

## 1. 为什么对话是核心

页面适合“看”和“点一下”，对话适合页面上一步做不到的事：

| 用户说 | 页面上要做的事 |
|---|---|
| “我周三考高数，操作系统挪到周末，今天只有一个半小时” | 改两门课的日程、改今日可用时间、重新分配——三个页面、十几次点击 |
| “银行家算法我还是没懂，换个说法，再给我出两道类似的题” | 找到知识点、换讲法、按知识点出题 |
| “把老师今天说的这几句加进去：……” | 打开重点页、粘贴、分析、确认 |
| “我是不是来不及了？” | 没有页面能回答 |

所以：**页面上能做的，对话都能做；对话的结果落回页面，两边看到的是同一份数据。**助手不是一个附加的聊天窗口，而是和页面并列的操作方式。

## 2. 入口与形态

| | 手机 | 平板 | 电脑 |
|---|---|---|---|
| 常驻入口 | 主页面底部输入条（标签栏上方）：“问点什么，或说说你今天的情况” | 右侧面板，可收起成一条细边 | 右侧面板，常驻，可调宽 |
| 展开 | 上滑为半屏弹层，再上滑全屏 | 面板展开 | 面板内滚动；可弹出为独立窗口 |
| 作答页 | 底部“求助”按钮，打开提示阶梯（第 4 节） | 右侧面板 | 右侧面板 |
| 历史 | 弹层顶部“对话记录” | 面板顶部 | 面板顶部 |

**自动带上下文。** 助手始终知道用户在看什么：当前课程、知识点、题目、选中的课件文字。输入框上方用“上下文标签”显示（例如「操作系统 · 银行家算法」），可点掉。用户不需要复制粘贴。

**三种输入方式之外的辅助：**

- `@`：引用对象——@课程、@资料、@知识点、@错题。对应 MCP 的“资源”。
- `/`：命令模板——/出题、/讲解、/提纲、/今天、/复盘，以及插件提供的命令。对应 MCP 的“提示模板”。
- 语音（手机、平板）、拍照（拍题、拍板书、拍笔记）、拖入文件（电脑）。语音转文字和拍照的文字识别由内置能力完成，不依赖主模型（04 第 4.3 节）。

**模型切换。** 面板顶部显示当前模型，可临时切换（只影响本对话）；默认模型在设置里改（04）。

## 3. 助手能做什么

助手的工具和页面调用同一套服务端接口（08）。按风险分三级：

| 级别 | 规则 | 工具 |
|---|---|---|
| 只读 | 随时调用，在回复里显示“查了什么” | 搜资料、读课件页、看课程概况、看知识点、看掌握度、看日程、看题目和错题、看用量 |
| 直接执行，可撤销 | 执行后出卡片，卡片上有“撤销” | 调整日程（挪动、跳过、限时）、勾选任务、加老师重点、选入 / 移除边界知识点、固定 / 放弃主题、开始一次练习（快练 / 按知识点 / 错题 / 复习 / 模拟卷）、给提示、给答案（记“看过答案”）、保存到笔记、设提醒 |
| 先提议，确认后执行 | 出“提议卡”，用户点“确认”才执行 | 改考试形式、改考试日期、删除资料 / 课程 / 练习记录、预计超出用量阈值的操作（04 第 5 节） |
| 不提供 | 只能在设置里做 | 密钥、账号安全、插件权限 |

**多步任务。** 用户一句话可能触发多个工具（“把这三份资料整理好，再排个两周的计划”）。助手先列出要做的几步（一张“任务卡”），预计超过 30 秒的步骤转为后台任务，卡片显示进度，用户可以离开，完成后通知。任何时候可以“停止”。

**过程透明但不啰嗦。** 工具调用折叠成一行（“查了课件第 12、13 页 · 出了 3 道题”），点开看细节。

## 4. 讲题：提示阶梯

作答中求助，分三级，逐级加强：

1. **方向**：这题考哪个概念、该先看什么（附课件页）。
2. **关键一步**：指出第一步怎么做，或列出解题需要的条件。
3. **完整解析**：给答案和过程。这一级之后，本题记为“看过答案”，答对也不计入掌握。

规则：

- 默认从第 1 级开始。用户明确说“直接告诉我答案”时跳到第 3 级，但先用一句话说明会记为看过答案。
- 提示不得泄露答案：服务端检查提示里是否含答案（v0.1 已实现单选字母、数值、主观题原文、排除法的检查），泄露就换成通用提示。
- **主动出现**：同一题停留超过 3 分钟、或同一知识点连续答错两次，输入条上浮一句“要不要提示？”。只出现一次，可在设置里关。
- 答完之后的追问（“为什么不选 B”）不受限制，直接讲。

## 5. 卡片：对话的产出物

助手的回复由文字和卡片组成。卡片是可操作的结构化内容，和页面上的对象是同一份数据。

| 卡片 | 内容 | 操作 |
|---|---|---|
| 改动卡 | 改了什么（日程、重点、知识点选择），改前 → 改后 | 撤销、查看 |
| 提议卡 | 将要改什么 | 确认、取消 |
| 题目卡 | 一道题，可直接在卡片里作答 | 作答、提示、在练习中打开 |
| 练习卡 | 一次快练 / 复习 / 模拟卷，题数、预计时长 | 开始 |
| 讲解卡 | 一段讲解 + 出处（课件页缩略图） | 看原页、讲简单点、考考我、保存到笔记 |
| 地图卡 | 一门课或一个章节的知识点地图片段 | 打开课程 |
| 日程卡 | 今天 / 本周的任务 | 打开日程、调整 |
| 任务卡 | 多步任务的步骤和进度 | 停止、查看结果 |
| 资料卡 | 上传 / 拍照的资料及处理状态 | 查看 |
| 用量卡 | 本次或本周的 token 用量和估算费用 | 打开用量 |
| 插件卡 | 插件提供的自定义卡片（第 8.5 节） | 按插件定义 |

卡片里的对象被删除或改动后，卡片显示最新状态（例如“这次调整已撤销”）。

## 6. 线程与记忆

- **线程**：每门课一条默认线程，外加一条“全局”线程（跨课程的话题，例如排日程）。用户可以新建线程。页面上点“问助手”时进入当前课程的线程。
- **学习档案（记忆）**：助手记住长期有用的事——作息（“晚上学效率高”）、偏好（“讲解要短”“喜欢先看例子”）、难点（“概率总是不会”）。规则：
  - 只记用户说过的或从作答中明确得出的（“连续三次答错条件概率”），不猜测性格、情绪。
  - 设置里可以看到全部记忆，逐条删除或关闭记忆。
  - 记住新东西时，回复下方出现一行“已记住：……”，可点撤销。
- 记忆和学情一起作为助手的上下文，按需读取，控制 token。

## 7. 主动性

助手只在三种时候主动说话，且都可以在设置里关：

1. **每日简报**：每天第一次打开时，今天页顶部一段两三句话的简报（“今天先把高数的级数收尾，操作系统昨天的错题有 4 道到期。”）。不推送通知，除非用户开了学习提醒。
2. **考后复盘**：交卷后在结果页给出一段复盘和下一步建议。
3. **卡住时**：第 4 节的主动提示。

## 8. 插件扩展系统

### 8.1 目标

不同课程的资料、知识类型和题型差别很大，内置能力覆盖不全（数学要公式和推导，编程要运行代码，语言课要背单词，设计课要画图）。插件让用户、团队成员或其他 agent 给助手加能力，不改主程序。

### 8.2 插件由什么组成

| 部分 | 格式 | 作用 |
|---|---|---|
| 技能 | Agent Skills 格式：`SKILL.md`（名称、描述、操作说明）+ 可选的脚本、参考资料、模板 | 教助手某类事怎么做：这门学科怎么讲、怎么出题、怎么判分 |
| 工具 | MCP 服务器（本地进程或远程地址） | 给助手新的动作：运行代码、算公式、画图、搜索 |
| 卡片模板 | 声明式 JSON，只能用固定的组件集合（第 8.5 节） | 在对话和页面里显示自定义内容 |
| 题型 | 渲染模板 + 判分工具 | 新的题目形式：程序填空、多选、画状态图 |
| 清单 | `plugin.json` | 身份、版本、包含哪些部分、权限、费用说明 |

清单示例：

```json
{
  "id": "code-runner",
  "name": "代码运行与判题",
  "version": "1.0.0",
  "description": "运行学生代码并判分，支持 Python、C、Java",
  "skills": ["skills/code-question/SKILL.md"],
  "mcp": { "command": "python3", "args": ["server.py"] },
  "cards": ["cards/run-result.json"],
  "question_types": [
    { "id": "code-fill", "name": "程序填空", "render": "cards/code-fill.json", "grade": "tool:grade_code" }
  ],
  "permissions": {
    "read": ["course.knowledge", "course.materials"],
    "write": ["questions"],
    "network": [],
    "model": false
  },
  "cost": "不调用模型"
}
```

### 8.3 扩展点

| 扩展点 | 例子 |
|---|---|
| 学科技能 | 高数（推导步骤、公式规范）、算法（手算过程表格）、英语（词汇与例句） |
| 题型 | 程序填空、多选、判断、画图题、证明题的步骤检查 |
| 资料解析 | 手写笔记识别、LaTeX 讲义、代码仓库、录音转笔记 |
| 工具 | 代码运行、符号计算、函数作图、网页搜索 |
| 导出 | Anki 卡组、PDF 提纲、日历（ICS） |
| 卡片 | 排序过程动画、状态机图、真值表 |

### 8.4 助手如何使用插件（渐进披露）

1. 启动对话时只把已启用插件的名称和描述放进上下文（每个约百字）。
2. 任务相关时读入对应的 `SKILL.md` 全文。
3. 需要时再读参考资料或调用工具。

这样装了十个插件，平时只多花十几行描述的 token——对自带密钥的用户很重要。

### 8.5 卡片模板

插件不能注入任意网页代码。卡片模板是一棵 JSON 树，只能用这些组件：文本、标题、图片、表格、代码块、公式、列表、进度、按钮（只能触发插件自己的工具或打开本应用的页面）、分栏。前端用 React 渲染，鸿蒙端用 ArkUI 渲染同一份模板。

### 8.6 运行与隔离

- 插件的 MCP 服务器在独立进程（或远程）运行，主服务通过 MCP 协议调用；超时、崩溃只影响这次调用，助手会说“插件没有响应”，并给出重试。
- 本地代码执行沿用现有沙箱（`server/workflow/sandbox.py`）的限制：无网络、限时、限内存。
- 插件要读课件、写题目、调模型，都通过主服务提供的接口，并且只能用清单里声明过的权限。
- 插件调用模型时用用户自己的密钥，计入用量，在用量页按插件分列。

### 8.7 权限与安装

- 安装时显示清单里的权限，用户确认后才安装；权限变化（升级）要重新确认。
- 插件可以全局启用，或只在某几门课启用。课程看起来需要某插件时（例如课件里有大量公式），课程主页给一条低调的推荐。
- 来源：内置、本地文件（zip）、链接（Git 仓库或网址）。插件市场是 P2。
- 插件返回的内容一律当作数据，不当作给助手的指令（防止插件或资料里的文字劫持助手）。

### 8.8 内置插件

内置能力也按插件形式实现，验证插件机制：

| 插件 | 来源 |
|---|---|
| 计算题求解（先算后写） | 现有 `workflow/compute_first.py` 与沙箱 |
| 代码运行与判题 | 新增 |
| 公式与图形渲染（LaTeX、Mermaid） | 新增 |
| 导出到 Anki / 日历 / PDF 提纲 | 新增（PDF 提纲属 P1） |
| 网页搜索 | 新增，默认关闭；开启后回答会区分“来自资料”和“来自网页” |

### 8.9 插件中心界面

`我的 → 插件`：已安装（开关、按课程启用、权限、用量）、内置可用、从文件或链接安装。插件详情页：说明、包含的命令和题型、权限、版本、卸载。

## 9. 回复风格

助手的说话方式决定产品有没有“AI 味”：

- 像一个靠谱的助教：短、具体、先给结论。默认三五句话，用户要展开再展开。
- 不寒暄、不夸奖、不道歉套话，不说“作为 AI”“希望对你有帮助”，不滥用表情和感叹号。
- 每个事实性的说法带出处；资料里没有就直说“课件里没讲到这个”，并可以问用户要不要用网页搜索（如已启用）。
- 能用卡片表达的不用大段文字；列表只在真的有并列项时用。
- 用户情绪低落时（“来不及了”）先给一个具体、能做到的下一步，不做空洞安慰。

## 10. 失败与边界

| 情况 | 表现 |
|---|---|
| 没连接模型 | 输入条可用，发送后回一张“连接 AI 模型”卡片，连接后自动重发 |
| 密钥失效 / 余额不足 | 说明服务商返回的原因，给“去更新密钥”按钮；已执行的动作保留 |
| 网络中断 | 消息标“未发送”，恢复后可重发 |
| 工具失败 | 说明哪一步失败、为什么，给重试；不假装成功 |
| 资料里没有 | 直说，不编 |
| 预计用量超过阈值 | 先出提议卡（04） |

## 11. 与现有实现的关系

v0 / v0.1 已有：意图识别（JSON 意图，原生工具调用作为备选）、直接执行 + 撤销、提议 + 确认、做题时先提示再给答案、答案泄露检查、出处核对。v1 在此基础上增加：上下文标签、@ 与 / 、卡片协议、线程与记忆、多步任务与后台任务、提示阶梯三级、主动提示、插件运行时。接口见 08。
